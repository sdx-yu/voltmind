## 基线决策摘要

| 主题 | v1.0 决策 |
|---|---|
| 产品定位 | 中文长篇作者的剧情操作系统 |
| 首要用户 | 10 万字以上、稳定更新的中文长篇/网文作者 |
| 核心闭环 | 完成本章 → 发现变化 → 作者确认 → 更新正典 → 下一章获得正确上下文 |
| 差异化 | 时态世界模型、正典事务、可解释 AI 上下文 |
| 客户端 | 桌面优先，React + TypeScript + Tauri 2 候选 |
| 编辑器 | Tiptap 候选，须先通过中文输入与长文 spike |
| 本地存储 | SQLite + FTS5，操作日志 + 不可变快照 |
| AI | 单一 OpenAI-compatible Provider 起步；候选式写入；可完全关闭 |
| MVP 周期 | 16 周开发 + 4 周真实种子验证 |
| 发布硬门槛 | P0/P1 缺陷为 0；不可恢复丢稿为 0；隐私字段泄漏为 0 |

## 版本管理

- `v1.0.x`：澄清、错字、链接等不改变范围的修订；
- `v1.x`：功能范围、流程或模型变化；
- `v2.0`：用户、定位或主要商业模式变化；
- 每次新基线应保留旧文件，并在新目录的 README 中记录取代关系；
- 重大技术决定使用 ADR，模板见里程碑文档。

## 阅读顺序

- 产品、设计、创业判断：先读产品规格，再读里程碑；
- 工程与 AI：先读数据与 AI 设计，再对照产品 FR 编号；
- 投资、合作或外部沟通：先读原始调研的“一句话结论”和本页决策摘要；
- 准备开工：三份规格都读，并先执行第 1–2 周验证，不直接跳到编码。
