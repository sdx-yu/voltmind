# 笔不怠 V1-D 交付体验层实施与验收报告 v0.6.0

日期：2026-08-26  
结论：工程验收通过，可作为 Apple Silicon 内测版继续使用；正式公开分发、真实平台过审与跨系统矩阵仍是外部门。

## 1. 本阶段范围

V1-D 将原始调研中的“耳朵校对”和“平台规则变化”落成两个本地闭环：

- 使用操作系统本地声音朗读当前选区、当前场景或所选章节；
- 提供声音、语速、播放、暂停、继续、停止和正在朗读句子的正文定位；
- 交付模板显示渠道、版本、核验日期、来源说明和过期阈值；
- 每条规则独立启停，结果显示规则编号、风险等级、命中文本和原文偏移；
- 检查不阻断 TXT、Markdown、DOCX 导出，也不会自动投稿；
- 朗读偏好、规则覆盖和检查记录进入完整离线备份与恢复。

明确没有实现云端 TTS、声音克隆、自动投稿、绕过审核或“检查通过即保证过审”。

## 2. 官方来源与模板边界

本版只内置“通用本地自检”和有可核验官方来源的番茄小说辅助模板，没有把无法稳定核验的第三方帖子写成起点/晋江官方规则。

- 番茄作家课堂入口：<https://fanqienovel.com/writer/zone/tutorial>
- 番茄签约流程说明：<https://fanqienovel.com/writer/zone/article/7198471813561581605>
- 番茄内容发布规范：<https://fanqienovel.com/writer/zone/article/7237084151751376957>

番茄模板版本为 `2026.08`，核验日为 `2026-08-26`，90 天后提示重新核验。规则仅把官方材料中可自动检查的窄问题实现为长段落、完全重复正文和 2 万字提示线；低俗、侵权、违法等语义风险保留为“人工确认”，不做虚假自动判定。

## 3. 数据与实现

SQLite schema 升至 v6，升级前自动生成 `pre-migration-vN-to-v6` 数据库备份。新增：

- `read_aloud_preferences`：项目声音、语速、音调；
- `delivery_templates` / `delivery_rules`：内置版本化模板与稳定规则编号；
- `project_delivery_rule_overrides`：项目级逐条开关和参数覆盖；
- `delivery_check_runs`：所选章节、命中结果、证据偏移与运行时间。

桌面端通过 Tauri WebView 的 Web Speech 系统接口使用本机声音，正文不进入远程 API。检查引擎只读取本地 SQLite 正文；人工规则不会伪装成自动结果。

备份恢复会按稳定规则编号重建覆盖，并把检查记录中的章节、场景 ID 映射到恢复项目的新节点，避免证据指向旧项目。

## 5. 真实界面验收

使用本地真实应用建立“V1-D 朗读交付验收”项目并写入 605 字未分段正文，完成以下闭环：

1. 系统列出 macOS 本地中文声音“婷婷”；
2. 当前场景实际开始朗读，显示正在朗读句子；
3. 暂停、继续、停止均改变可见状态，停止后位置清空；
4. 番茄模板显示版本 `2026.08`、核验日和官方来源；
5. 首次检查得到 `FQ-FMT-001` 和 `FQ-SIGN-001` 两条提醒；
6. 关闭 `FQ-FMT-001` 后重新检查只剩 1 条，恢复后再次出现；
7. 点击命中证据“定位”返回场景 1 正文；
8. 所选章节的 TXT、Markdown、DOCX 和完整备份入口同时可用。

真实验收发现并修复两个缺陷：连续修改声音和语速时旧保存响应覆盖新状态；模板/历史接口未返回时交付页把两个空值误判为同一模板而崩溃。两项均增加组件回归测试后再执行全量门禁。

## 7. 未关闭的外部门

- Apple Developer ID 签名和公证尚未执行，当前包只适合内测；
- Windows 11、多个 macOS 大版本、输入法和缩放矩阵仍需真机；
- 系统声音数量与质量取决于用户操作系统已安装语音；
- 平台规则可能变化，90 天提示不能替代发布前重新查看官方规则；
- 平台实际过审、签约和投稿只能由真实作者账号验证；
- 50 万字全书检查的后台取消仍属于发布前性能门。

## 8. 下一阶段

V1-D 工程门通过。下一阶段已冻结为 V1-E `0.7.0`：把人写、AI 候选、作者接受、接受后人工修订、导入与恢复整理成可回放来源链，并导出默认不含正文、可离线校验的证明包。
