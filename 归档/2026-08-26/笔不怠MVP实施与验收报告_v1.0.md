## 1. 交付内容

- 本地书架、书—卷—章—场景树、Tiptap 长篇编辑器、900ms 自动保存、不可变版本和 Diff 恢复；
- FTS5 中文搜索，正文/标题/正典范围替换，替换预览与整批事务撤销；
- TXT/Markdown/DOCX 导入切章预览，原件 SHA-256 留存，失败不创建半项目；
- TXT/Markdown/DOCX 范围与模板导出，`bbd-backup-v2` 完整离线备份和校验还原；
- 人物/地点/物品/事件，时态状态、Mention 反链、锚点修复、场景状态投影；
- 完成场景后的事实候选、证据、before/after、生效点、接受/修改后接受/忽略和 CanonEvent 哈希链；
- 专名、死亡状态、持有关系和 ISO 故事时间检查，证据展示与持久例外；
- OpenAI-compatible Provider、本地演示模型、上下文胶囊、隐私过滤、token 估算、AI 原文/候选 Diff、句级部分接受和撤销；
- 日目标、项目目标、今日净新增、专注模式、设备级字号/纸宽设置、交付台和多层回收站；
- SQLite 启动/退出/10 分钟快照、最近 20 份 + 最近 7 日每日一份轮换、迁移前副本、快照完整性校验。

## 2. 自动化结果

最终命令：

```text
npm run check
typecheck: passed
vitest: passed
vite production build: passed
npm audit --audit-level=high: 0 vulnerabilities
```

覆盖的关键不变量：

- 不可变版本与恢复为新版本；
- 中文搜索索引；
- 时态区间不重叠；
- Candidate 接受与 CanonEvent 同事务；
- Mention 只建议不静默确认、正文移动后锚点修复；
- 替换批次原子提交和精确撤销；
- 节点递归软删除/恢复；
- 20 万字符保存与检索；
- 备份跨新项目恢复正文、版本、Mention、设置，篡改校验失败不覆盖；
- 原件哈希或长度错误时取消导入且项目数不变；
- TXT/MD 范围导出和 DOCX 重新读取；
- API Key 不以明文入库或返回；
- 非法 Origin 和无本地会话写请求被拒绝；
- 数据库快照完整性与 20+7 轮换。

## 3. 真实浏览器端到端验收

在应用实际界面完成：

1. 无账号创建“验收样稿”，输入中文正文，约 900ms 后显示“已保存到本机”，重载后正文与版本哈希仍在；
2. 服务热重载使会话令牌轮换后，前端自动重新获取 loopback 会话并继续创建正典；
3. 创建林照、沈砚、佩剑，正文自动建议 4 个 Mention，逐项确认后显示反链；
4. 点击“完成本场景并提取事实”，生成“佩剑交给林照”的 90% 候选，展示旧值、新值与原句证据；
5. 接受候选后写入 `holder=林照`，场景检查器显示该时点状态，候选箱归零；
6. 全局替换“没有立刻 → 仍未”，预览 1 处，原子应用后整批撤销，正文恢复；
7. 展开上下文胶囊，看到 5 项、原因、隐私与约 67 token；本地演示 AI 生成 4 句，取消其中 2 句后只接受 2 句，正文留痕，再从 AI 面板撤销接受；
8. 进入专注模式后书稿树、顶栏和检查器隐藏；退出后三栏布局完整恢复；
9. 新建卷并在卷下新建章节/场景，结构与选择状态正常；
10. 书架与写作台分别完成视觉截图检查，空状态、错误提示、键盘焦点和响应式规则已配置。

## 4. 性能证据

同机合成基准（Node 24、SQLite WAL、SSD）：

| 场景 | 实测 | 规格门槛 | 结论 |
|---|---:|---:|---|
| 打开并读取 20 万字符项目 | 6.71ms | ≤ 2s | 通过 |
| 20 万字符中文全文搜索 | 422.62ms | ≤ 1s | 通过 |
| 保存 1 万字符场景 | 8.97ms | 后台主线程目标需浏览器 profiling | 数据层通过 |
| 50 万字符基础规则检查 | 14.27ms | ≤ 10s | 通过；当前同步执行，取消按钮待后台任务化 |
| 真实编辑器单场景 20 万字符压力写入 | SQLite 最终长度 200000，自动保存成功，清空操作 82ms | 项目级无明显卡顿 | 数据正确；CDP 在返回超大 DOM 时超时，不能据此声明输入 P95 |

这些数字是一次工程基准，不等价于 P95。正式发布仍需在 4 核/8GB 的目标 Windows 和 macOS 设备重复采样。

## 5. 恢复与生产演练

- 生产构建静态首页、SPA fallback、`/api/health` 均返回 200，数据库 `integrity_check=ok`；
- 在独立临时目录创建项目并保存“强杀前已经落盘的正文。”，对服务进程发送 `SIGKILL`；
- 使用同一数据库重启后，完整性检查为 `ok`，正文逐字恢复，版本数为 1；
- 演练创建的临时目录和临时系统钥匙串项均已删除；
- 启动快照、退出快照、10 分钟周期快照会先 checkpoint，再校验临时副本，最后原子改名；校验临时 WAL/SHM 已确认不会残留。

## 6. 隐私与安全检查

- 服务只监听 `127.0.0.1`，使用 HttpOnly、SameSite=Strict 本地会话 Cookie；
- 非允许 Origin 在会话建立前即被 403 拒绝；
- 生产 macOS 使用系统钥匙串保护 32 字节主密钥，API Key 以 AES-256-GCM 密文存入 SQLite；开发/测试回退到权限 `0600` 的本机密钥文件；
- `ai_tasks` 只记录模型、任务类型、Prompt 版本、上下文哈希、token 数与输出哈希，不记录 Prompt、正文和 Key；
- `local_private` 上下文项在界面不可勾选，服务端提交前再次过滤；
- 当前产品没有遥测、崩溃上传和诊断包，因此不会外发正文；未来增加这些能力前必须另行验收脱敏与二次确认。

## 7. 未通过的发布门禁

以下不是隐藏缺陷，而是本轮环境无法完成或尚未进入桌面发布链的明确阻断项：

1. **桌面分发**：当前是本机服务形态；Tauri/原生安装包、签名、自动更新签名和卸载尚未实现；
2. **真机输入法矩阵**：尚未在 Windows 11 微软拼音/搜狗，以及两个 macOS 大版本系统拼音执行组合态、候选词、全角标点和 100%–200% 缩放回归；
3. **损坏库救援**：正常 WAL 强杀恢复已通过，但“数据库已损坏时只读打开并从快照恢复”的专用救援界面尚未实现；
4. **跨平台凭据库**：macOS 生产路径已接系统钥匙串；Windows Credential Manager 要随桌面壳补齐；
5. **后台取消**：50 万字符规则检查实测很快，但目前同步执行，没有可取消后台任务；
6. **发布治理**：SBOM/许可证归档、安装包签名、自动更新、正式版本回滚包尚未建立；
7. **外部产品验收**：规则 precision、证据定位率、20 位种子作者四周留存与付费意愿必须由真实样本验证。

因此，本报告对“本机功能 MVP”给出通过，对“公开发布候选”给出 **NO-GO**。下一门禁应先完成桌面壳与真机输入/恢复矩阵，而不是继续增加新功能。
