## 1. 产品定义

### 1.1 一句话定位

**笔不怠是中文长篇作者的剧情操作系统：作者专注写，系统负责保存、关联、查错和记住故事如何变化。**

### 1.2 核心问题

当作品进入数十万字后，作者需要同时维护正文、人物设定、事件时间、物品流转、人物关系和伏笔。现有产品通常把它们存成互不相干的静态卡片，AI 又可能引用过期设定或把未确认的草稿当成事实。

笔不怠解决的不是“如何多生成一段文字”，而是：

1. 当前场景真正相关的事实是什么；
2. 哪些事实已经发生变化；
3. 哪些变化已由作者确认；
4. 下一章的作者或 AI 应该知道什么、不应该知道什么；
5. 出错后如何找到证据、回滚并恢复。

### 1.3 产品承诺

- **不丢稿**：默认本地保存，自动快照，可离线写，可完整导出。
- **不越权**：AI 不直接改正文、不直接改正典。
- **不糊弄**：任何冲突提示都提供证据位置、规则和置信度。
- **不绑架**：正文与元数据均可导出，不以专有格式锁死作者。
- **不喧宾夺主**：默认工作台保持安静，复杂规划能力按需展开。

### 1.4 北极星场景

作者写完第 39 章并点击“完成本章”：

1. 系统保存不可变快照；
2. 系统发现“佩剑从沈砚转交给林照”和“沈砚得知密道”两项事实变化；
3. 右栏显示原句证据、旧状态、新状态和影响范围；
4. 作者接受第一项、修改第二项、忽略一个误报；
5. 正典库和时间线更新；
6. 写第 40 章时，上下文只包含林照持剑这一当前状态，并区分读者已知与角色已知。

只有这条闭环被真实作者持续使用，MVP 才算成立。

## 2. 目标用户与任务

### 2.1 首要用户：稳定连载作者

| 属性 | 描述 |
|---|---|
| 作品规模 | 10 万–300 万字，按卷和章连载 |
| 写作节奏 | 日更或周更，最怕丢稿和断更 |
| 当前工具 | Word/WPS + 便签/表格，或现有码字软件 |
| 主要痛点 | 设定散、前文难找、时间线穿帮、人物状态记错、发布前重复检查 |
| 购买理由 | 少翻资料、少返工、跨设备安心、提高稳定更新能力 |
| AI 态度 | 愿意用脑暴、校对、检查；担心文风变味、隐私和越权修改 |

关键 JTBD：

> 当我每天继续写一个越来越长的故事时，我希望工具自动把与当前场景相关的设定和历史变化放到手边，并在我确认后更新，以便我不断更、不穿帮，也不用把作品交给 AI 决定。

### 2.2 次要用户：规划型类型小说作者

- 一次完成 10 万–50 万字小说或系列作品；
- 重视人物弧、伏笔、因果和版本修改；
- 购买理由是 Plot Grid、双时间线、连续性检查和系列正典；
- 在 V1 才完整覆盖，不以其高级需求拖慢 MVP。

### 2.3 暂不服务

- 只写几百字日记或短社交文案的用户；
- 论文、公文和知识库团队；
- 追求一键批量生成整本书的内容农场；
- 第一版需要多人实时共同编辑的编剧室。

## 3. 成功定义

### 3.1 MVP 产品假设

| 编号 | 假设 | 验证信号 |
|---|---|---|
| H1 | 长篇作者愿意维护“动态正典” | 导入/新建项目中，60% 以上用户确认至少 10 条事实候选 |
| H2 | 候选式 AI 比直接改写更可信 | 70% 以上测试用户能准确说出 AI 改了什么；候选有实际接受行为 |
| H3 | 连续性检查能减少翻资料 | 核心用户自报查资料时间下降 30%，或可观察任务完成时间下降 |
| H4 | 本地优先与可导出能建立迁移意愿 | 访谈中不再把“稿件安全/被锁死”列为首要阻碍 |
| H5 | 作者愿意为同步和高级检查付费 | 有明确付费意愿的有效测试用户达到 25% 以上 |

### 3.2 MVP 成功门槛

- 20 位种子作者中至少 12 位完成 4 周试用；
- 至少 8 位每周使用一次“完成本章 → 确认事实”闭环；
- 一致性警告人工确认精确率不低于 80%；
- 事实候选接受或修改后接受比例不低于 60%；
- 任何测试项目不得出现不可恢复丢稿；
- 20 万汉字项目的打开、全局搜索、保存和切章达到性能指标。

## 4. 产品原则与关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| AI 主交互 | 任务按钮 + 上下文胶囊 + 候选 Diff | 聊天可保留，但不让它成为数据入口和主导航 |
| 数据权属 | 本地项目为主，云同步为可选服务 | 稿件安全是信任底座 |
| 正典更新 | 人工确认后生效 | 防止模型误抽取污染后续上下文 |
| 信息组织 | 正文层级 + 实体/事件图并存 | 树适合写作，图适合关系与因果；不能只选一种 |
| MVP 平台 | 桌面优先 | 长篇生产主场在桌面，先把可靠性做稳 |
| MVP 协同 | 不做实时合著 | 同步与协同的复杂度不同，先解决单人多设备和备份 |
| AI 供应商 | 单一 OpenAI-compatible 接口起步 | 先验证体验，不做模型超市 |
| 检查方式 | 确定性规则优先，LLM 补充 | 提高可解释性、速度和成本可控性 |

    │   └── 场景检查器 / AI 候选
    ├── 剧情台
    │   ├── 场景矩阵
    │   ├── 叙述顺序
    │   └── 故事时间 / 因果图（V1）

    │   ├── 人物 / 地点 / 组织 / 物品 / 规则
    │   ├── 事件
    │   └── 伏笔（V1）
    ├── 交付台
    │   ├── 质量检查
    │   ├── 预览
    │   └── 导出 / 完整备份

## 6. 核心对象与状态

### 6.1 项目层级

- 项目：一部单本书或系列的工作空间；MVP 一个项目对应一本书。
- 卷：可选层级，不强迫短篇用户创建。
- 章：导出与发布的主要单元。
- 场景：连续性、POV、人物状态和 AI 上下文的最小语义单元。

### 6.2 场景状态

```text
想法 → 计划 → 草稿 → 修订 → 完成 → 已发布
                    ↘ 退回草稿
```

- 状态只用于工作流，不代表质量判断；
- “完成”会触发快照和事实候选提取；
- 已发布场景再次修改时必须明确创建新修订，避免静默改变已发布内容。

### 6.3 候选变化状态

```text
待处理 → 接受
      ├→ 修改后接受
      ├→ 忽略一次
      └→ 永久规则例外
```

- 接受与修改后接受会产生 Canon Event；
- 忽略不删除记录，用于评估误报；
- 永久例外必须限定项目和规则，避免全局压制有价值提示。

### 6.4 同步可见状态

- `已保存到本机`
- `等待同步`
- `已安全同步`
- `同步暂停：离线`
- `需要处理冲突`

禁止只用一个含义模糊的云朵图标。

## 7. 关键用户流程

### 7.1 新建项目

1. 选择空白、网文连载或类型小说模板；
2. 填写书名，卷结构可跳过；
3. 选择“纯手写 / AI 仅检查 / AI 可辅助创作”；
4. 选择本地项目位置与自动备份位置；
5. 进入第一章，示例内容不写入正式稿。

完成标准：首次打开后 60 秒内可以输入正文；没有任何必填世界观表格。

### 7.2 导入旧稿

1. 导入 TXT、Markdown 或 DOCX；
2. 展示章节识别预览，允许按标题、空行、正则或手工重新切分；
3. 保存原文件副本和导入报告；
4. 正文先可写，正典抽取在后台分批运行；
5. 候选按人物、地点、物品和事件分组，每批不超过 20 条；
6. 作者可跳过抽取，不阻塞使用。

完成标准：20 万汉字 TXT 在目标机器上 30 秒内完成可编辑导入；识别失败不损坏原文件。

### 7.3 日常写作

1. 从最近场景继续，左栏显示今天目标和同步状态；
2. 右栏默认只显示场景卡和相关正典，AI 工具折叠；
3. `@人物名` 或已有名称触发实体建议，不强制打断输入；
4. 每 2 秒空闲保存一次操作；每 5 分钟或重大操作生成轻量快照；
5. 离开场景时记录阅读位置、字数变化和状态。

完成标准：保存不造成可感知输入卡顿；断网后全部核心编辑功能正常。

### 7.4 完成本章与更新正典

1. 点击“完成本章”；
2. 立即生成本地快照，不等待 AI；
3. 运行确定性检查并展示结果；
4. 若用户允许，再调用 AI 抽取事实变化；
5. 每条候选显示旧值、新值、生效点、证据句和影响实体；
6. 作者批量或逐条确认；
7. 被接受项原子写入正典、事件日志和反链；
8. 显示“本章使故事发生了什么变化”的摘要。

失败降级：AI 不可用时，本章仍能完成，规则检查和快照不受影响。

### 7.5 使用 AI 修改正文

1. 选中文本或当前场景；
2. 选择任务：脑暴、续写、压缩、改写、对白检查、冷读反馈；
3. 打开上下文胶囊，默认列出引用项和排除项；
4. 用户可增删上下文、选择是否发送私密字段；
5. 显示模型、预计 token/费用后执行；
6. 输出进入并排 Diff，不写进正文；
7. 用户可接受选中句、全部接受、复制或丢弃；
8. 接受动作记录来源，作者后续修改仍标为“AI 建议后人工修订”。

完成标准：用户永远有机会在持久化前看见完整变更。

### 7.6 恢复与备份

1. 历史面板按时间、章节和操作类型筛选；
2. 选择任意版本查看逐行 Diff；
3. “恢复为新版本”而非覆盖删除当前版本；
4. 完整备份包含正文、正典、版本、附件、设置和校验清单；
5. 新设备可在无网络环境下从备份还原。

## 8. 页面规格

### 8.1 书架

必须显示：封面、书名、最近编辑时间、总字数、同步状态、最近场景。

操作：新建、导入、打开、复制、归档、导出备份、移入回收站。删除必须先进入回收站，默认保留 30 天；永久删除需二次确认并明确不可恢复。

空状态文案：`故事还没开始。新建一个空白项目，或把旧稿带进来。`

### 8.2 写作台

布局：左栏 260px 可折叠；中心编辑区自适应；右栏 320–420px 可折叠。窗口过窄时右栏变抽屉。

必须能力：

- 章/场景拖动、拆分、合并、复制和软删除；
- 自动标题与自定义标题；
- 撤销/重做、搜索替换、中文标点、粘贴纯文本；
- 字数、选中字数、今日新增、目标差值；
- 专注模式、打字机滚动、明暗主题、字号/行高/段宽；
- 快照入口和保存/同步状态；
- 右栏在“场景、正典、检查、AI”四个页签间切换。

关键防误触：拖动章/场景必须有清晰落点；跨卷移动后显示撤销 Toast；删除不使用仅图标且无文本的危险按钮。

### 8.3 正典库

列表支持类型、标签、出场状态和未处理候选筛选。详情页至少包含：名称、别名、简介、恒定事实、时态状态、关系、首次/最近出场、正文反链、私密级别、修订历史。

同名处理：

- 名称完全相同但实体不同，必须要求区分显示名；
- 别名冲突时只给建议，不自动合并；
- 实体合并前展示会改写的 Mention 数和状态数，并保留可撤销映射。

### 8.4 交付台

检查分组：阻断问题、建议复核、风格建议。只有文件无法生成、正文为空或编码失败属于阻断；敏感词、未回收伏笔不得阻断导出。

每次导出生成报告：格式、范围、字数、时间、模板版本、文件校验值。导出过程中不改变正文格式模型。

## 9. MVP 功能需求与验收

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---:|---|
| FR-001 | 本地项目创建与打开 | Must | 无账号、无网络可创建并重开项目；异常退出后可恢复到最近保存 |
| FR-002 | 书—卷—章—场景树 | Must | 支持增删改、拖动、拆分、合并；所有危险操作可撤销 |
| FR-003 | 长篇正文编辑 | Must | 20 万汉字项目连续输入无明显卡顿；中文输入法组合态不丢字、不乱光标 |
| FR-004 | 自动保存与快照 | Must | 编辑后 2 秒内落本地操作日志；快照可预览 Diff 并恢复为新版本 |
| FR-005 | 全局搜索替换 | Must | 可限定正文/标题/正典；替换前预览命中，替换动作可整体撤销 |
| FR-006 | 导入 TXT/MD/DOCX | Must | 预览章节切分；保留原件；失败提供可读报告且不产生半成品项目 |
| FR-007 | 导出 TXT/MD/DOCX | Must | 可选范围和模板；重新导入后正文、章序和标题不丢失 |
| FR-008 | 完整备份/还原 | Must | 在另一台离线设备还原正文、正典、版本与附件；校验失败时阻止覆盖 |
| FR-009 | 基础正典实体 | Must | 人物/地点/物品/事件可增改、软删除、搜索、查看正文反链 |
| FR-010 | 时态状态 | Must | 同一属性可有多个不重叠有效区间；查看任意场景时显示当时值 |
| FR-011 | Mention 反链 | Must | 自动建议后由用户确认；点击可定位原句；正文移动后锚点可修复 |
| FR-012 | 事实变化候选 | Must | 候选含证据、旧值、新值和生效点；接受过程为原子事务 |
| FR-013 | 基础一致性检查 | Must | 覆盖专名、状态、持有关系和故事时间；提示带证据且可忽略 |
| FR-014 | AI Provider 配置 | Must | OpenAI-compatible URL/Key/模型可测试；Key 加密保存且日志不泄露 |
| FR-015 | 上下文胶囊 | Must | 执行前可查看、增删引用项、看到隐私状态和 token 估算 |
| FR-016 | AI 候选 Diff | Must | 原文不被直接覆盖；支持句级部分接受、全部拒绝、撤销接受 |
| FR-017 | 写作目标与基础统计 | Should | 日目标、项目目标、今日净新增准确；粘贴大段文字与撤销不虚增 |
| FR-018 | 专注模式与显示设置 | Should | 设置按设备保存；退出专注后布局完整恢复 |
| FR-019 | 回收站 | Must | 项目/章/场景/实体均先软删除；可恢复原位置或选择新位置 |
| FR-020 | 操作与来源记录 | Must | 记录人写、AI 建议、接受、恢复、导入，不记录 API Key 与私密正文日志 |

## 10. 非功能需求

### 10.1 可靠性

- 正文持久化不依赖远程服务；
- 所有跨多表写入使用事务；
- 启动时执行完整性检查，异常时只读打开并提供备份恢复；
- 自动备份采用轮换策略，至少保留最近 20 份和最近 7 天每日一份；
- 任何自动迁移先生成数据库备份并验证可回滚。

### 10.2 性能基线

目标测试机：4 核 CPU、8GB 内存、SSD 的中端设备。

- 冷启动到书架：P95 ≤ 3 秒；
- 打开 20 万汉字项目：P95 ≤ 2 秒；
- 切换 1 万汉字段落场景：P95 ≤ 300ms；
- 输入到可见：P95 ≤ 50ms；
- 自动保存主线程阻塞：P95 ≤ 16ms；
- 20 万汉字全局搜索：P95 ≤ 1 秒；
- 50 万汉字基础规则检查：P95 ≤ 10 秒，可取消且不阻塞编辑。

### 10.3 隐私与安全

- API Key 使用系统凭据库；
- 默认不收集正文、Prompt、正典内容或文件名；
- 崩溃报告正文脱敏，发送前可预览；
- 每个正典字段可设为本地私密，私密字段不进入云 AI 上下文；
- 导出诊断包需二次确认并列出包含内容；
- 自动更新包必须签名并验证。

### 10.4 可访问性与中文体验

- 所有主要操作可键盘完成；焦点样式清晰；
- 颜色不是状态的唯一表达；
- 支持系统缩放 100%–200%，正文可独立调字号/行高/段宽；
- 对 Windows/macOS 常用中文输入法做组合态、候选词和全角标点回归；
- 字数统计明确采用“汉字与非空白词元”还是“字符数”，并允许切换显示口径。

## 11. 埋点与隐私边界

默认只采集匿名功能事件，且可完全关闭：

- 项目创建/导入是否成功；
- 功能入口使用次数；
- 候选接受/修改/忽略状态；
- 检查规则确认/误报状态；
- 性能、崩溃和同步错误码。

严禁采集：正文内容、实体名称、书名、Prompt 文本、API Key、导出文件名。所有指标在设计时都必须能在没有内容数据的情况下计算。

## 12. MVP 不做清单

- 实时多人合著与评论权限体系；
- Android/iOS 完整编辑器；
- 内容广场、作者关注、排行榜；
- 一键生成整本书和无人值守多代理流水线；
- 自建模型训练、微调平台；
- 复杂纸书排版、封面商城；
- 关系图自由白板和地图编辑器；
- 自动发布到各网文平台；
- 对平台审核结果作保证。

新增需求若无法证明服务于北极星闭环，默认进入 V1/V2 候选，不进入 MVP。
