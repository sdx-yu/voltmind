# 笔不怠 UI-F 表单与浮层统一验收报告 v2.2.0

日期：2026-08-28  
结论：**UI-F 本机工程、macOS Chrome 代表环境与 2.2.0 Apple Silicon 内测包验收通过**。原生选择浮窗和正典搜索框的两类可见问题已修复，业务页面的原生 `<select>` 已归零；公开发布状态不变。

## 问题与设计判断

- 原选择浮窗由操作系统绘制，系统蓝色、圆角、行高和弹层尺寸无法由项目 CSS 可靠控制，因此必须替换控件实现，而不是继续修饰原生 `select`。
- 正典搜索框同时存在旧 `.canon-search` 容器和新字段样式，造成双层边框、背景叠加和异常高度；修复采用单层组合控件，不再保留装饰性外壳。
- 输入框不应直接等同纸张背景。新增独立控件表面语义，使宣纸、夜间和高对比主题能分别决定默认、悬停和禁用背景。

## 已完成

- 新增品牌化 `SelectControl`，支持触发器等宽浮层、视口碰撞避让、最大高度、滚动按钮、项目绿选中态、禁用项和状态图标；
- `SelectField` 统一使用自定义浮层，同时兼容既有 `onChange` 业务调用，未改动 API 或数据结构；
- 新增单层 `SearchField`，内置搜索图标和有内容时才出现的清空按钮；
- 新增控件默认、悬停、禁用表面及菜单行高/限高语义变量；
- 检查器的进度、视角、故事时间与知识面板完成迁移；正典搜索框完成结构清理；
- 交付、移动、规划、来源、朗读、研究、审阅、系列、设置、冲刺、视觉和工作区等业务选择器全部迁移；
- 静态门新增原生选择器扫描，后续业务组件出现 `<select>` 将直接失败；
- 组件展厅升级至 UI-A～UI-F / 2.2.0，展示搜索、选择和清空交互。

## 边界与后续

- 本轮使用自定义 ARIA Listbox 行为，后续新增选择场景必须复用 `SelectControl` / `SelectField`，不得直接新增原生 `select`；
- 可输入下拉、多选和超大数据虚拟列表未被现有需求触发，不在本阶段范围；
- 2.2.0 Apple Silicon 内测 App ZIP 与 DMG 已完成，可交给明确知情的内部测试者；正式 Developer ID 签名、公证、Windows 和移动真机仍未交付，不能把本包宣传为公开发布版本。
