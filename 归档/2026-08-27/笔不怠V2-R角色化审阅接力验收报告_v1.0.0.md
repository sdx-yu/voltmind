## 1. 阶段目标与结论

V2-R 对应原始调研 V2 的第一项“Editor、Beta Reader、Co-Writer 角色和段落级批注”。本阶段完成离线、加密、可审计的角色化审阅接力：作者只分享指定场景的隔离副本，审阅者带回批注或局部建议，作者逐条接受、拒绝或搁置。审阅者不取得项目写权限，外部意见不能静默改写正文、正典或来源链。

工程验收结论为通过。最终 `npm run check` 完成 24 个测试文件、81 项测试，TypeScript 与生产构建均通过；两个隔离 SQLite 进程完成真实浏览器接力；macOS Apple Silicon 的 1.0.0 应用与 DMG 已构建、校验并完成本机启动冒烟。公开发布仍为 NO-GO：当前仅 ad-hoc 签名，尚无 Developer ID 签名、Apple 公证和真实在线身份系统。

## 2. 主要交付

### 2.1 角色与作者最终决定

| 角色 | 可提交批注 | 可提交局部改写 | 可直接改正文/正典/来源 |
|---|---:|---:|---:|
| Editor | 是 | 是 | 否 |
| Beta Reader | 是 | 否 | 否 |
| Co-Writer | 是 | 是，仅作者指定范围 | 否 |

- 作者创建任务时选择角色、审阅者名称、场景范围、可选来源摘要和到期说明；
- 审阅者工作台可在本机无项目、无账号的情况下打开任务；
- 批注支持段落引用；改写建议显示原文—建议 Diff；
- 作者对每条反馈执行接受、拒绝或搁置，接受建议才生成新正文版本并追加“接受审阅改写建议”来源事件；
- 拒绝和搁置不改变正文；已应用建议保持“已应用”状态，不被误报为锚点失效。

### 2.2 可重定位锚点

- 段落锚点保存选中文本、段落内容哈希、上下文摘要与偏移；
- 当前正文未变化时返回“精确”；正文移动但上下文仍满足阈值时返回“候选”；无法可靠定位时返回“失效”；
- 多换行正文使用顺序查找定位，不假设段落之间只有一个换行；
- 失效锚点禁止自动接受改写，必须由作者人工处理，系统不猜测落点。

### 2.3 `bbd-review-v1` 加密协议

- 任务包与回应包使用相同冻结格式，包外仅保留协议路由和密码学参数；项目标题、审阅者、角色、场景正文和反馈均位于密文内；
- 192-bit 一次性恢复短语；scrypt `N=32768/r=8/p=1` 派生密钥；AES-256-GCM 加密；协议头作为 AAD；密文另有 SHA-256 完整性校验；
- 恢复短语不写入包、数据库或普通备份；
- 限制最多 100 个场景、5 MiB 明文和 10 MiB 封装；错误短语、篡改、跨项目导入、重复 ID 异载荷、越权角色和越界场景均明确拒绝；
- 相同包重复或乱序导入幂等，不重复创建反馈和作者决定。

### 2.4 数据、API、备份与恢复

- SQLite migration v10 新增审阅会话、反馈、作者决定与任务时场景快照；升级前生成 v9→v10 备份；
- 对早期 v10 草案数据库执行兼容性自修复，补齐缺失的 `scene_snapshots_json`，真实旧开发库已验证可继续创建任务；
- API 覆盖创建、列表、导出任务、预检、导入、添加反馈、导出回应和作者决定；
- 普通 `bbd-backup-v2` 可保存审阅历史，但不包含恢复短语、派生密钥、salt、nonce、认证标签或密文；
- 恢复后的审阅历史标记为归档，不会冒充仍可继续的活动会话；项目清理同步移除审阅数据。

## 4. 真实浏览器验收

使用作者端和审阅者端两个隔离的数据目录与 SQLite 进程完成闭环：

| 场景 | 结果 |
|---|---|
| 作者创建任务 | 创建项目“V2-R 角色审阅验收”，选择 Editor 与一个场景，生成加密任务包和一次性恢复短语 |
| 无项目审阅入口 | 审阅者端空书架可直接进入“打开审阅任务”，无需先创建本地项目 |
| 隔离导入 | 审阅者端导入后 `projectId` 为空，仅保存指定场景副本，未获得作者项目权限 |
| 段落建议 | 对“必须作出选择”提交“必须在午夜前作出选择”，并附“这里可以更有决断感。” |
| 回应接力 | 审阅者导出加密回应，作者端导入后显示精确锚点、Diff 和接受/拒绝/搁置 |
| 作者接受 | 浏览器点击接受后正文变为“顾临知道今晚必须在午夜前作出选择。” |
| 来源证明 | 来源时间线显示“接受审阅改写建议”事件 |
| 视觉检查 | 1280×720 的作者处理台与审阅者工作台布局、层级和反馈状态正常 |

当前浏览器控制环境不能向系统文件选择器注入文件，因此浏览器阶段通过同一认证 API 在两个隔离进程间传递实际加密包；文件控件读取和预检后导入的完整 UI 路径由组件测试使用真实 `File` 对象覆盖。0.9.0 已有 360/390/430px 窄屏回归，本阶段没有新增真机或窄屏浏览器矩阵。
