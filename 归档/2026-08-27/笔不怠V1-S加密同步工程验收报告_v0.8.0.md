# 笔不怠 V1-S 加密同步工程验收报告 v0.8.0

- 日期：2026-08-27
- 结论：本机工程门通过；真实云端、账号和真实双设备门未执行
- 版本：0.8.0
- 协议：`bbd-sync-v1`

## 1. 阶段结论

V1-S 把原始调研中的“先做单人多端离线同步，再开放实时协作”落成可审计工程底座：项目仍以本地 SQLite 为主副本，作者手动导出/导入端到端加密接力包；正文通过 Yjs 更新合并，正典、删除与来源链按业务语义进入显式冲突。

本阶段完成的是两个隔离本地副本和真实本机界面的工程验证，不等同于云服务上线，也不等同于两台真实设备、账号、运维和合规门通过。

## 2. 协议与数据实现

SQLite schema 升至 v8，升级前继续生成 `pre-migration-vN-to-v8` 副本。新增：

- `sync_project_configs`：设备 ID/名称、盐、密钥验证值、本机序号和版本向量；
- `sync_scene_states`：场景 Yjs 完整状态、状态向量和正文哈希；
- `sync_object_versions`：场景/正典对象版本向量、内容哈希和删除墓碑；
- `sync_updates`：发送/接收包、密文哈希、状态和应用时间；
- `sync_conflicts`：正典并发、删除/编辑和来源链分叉及作者决定。

加密与传输：

- 恢复短语为 24 随机字节、12 组十六进制，初始化时只显示一次；
- scrypt N=32768、r=8、p=1 派生 256 bit 密钥；本机只保存随机盐和 HMAC 验证值；
- 完整载荷使用 AES-256-GCM；信封头进入 AAD；密文按 64 KB 分块并逐块/整包 SHA-256；
- 包中标题、正文、正典、来源链、版本和附件均为密文；信封仍暴露设备代号、时间、序号、版本向量和近似大小等必要元数据；
- 导入原件附件以 `sha256:<digest>` 寻址，导出和落库前复核字节数与哈希。

协议与威胁边界已冻结在 `docs/implementation/SYNC_PROTOCOL_V1.md`，重大决定记录在 ADR-003。

## 3. 合并与作者决定

- Yjs 文档更新具备交换、结合和幂等性质，适合作为离线文本合并底层；V1-S 使用 `Y.Text`，并继续把剧情时间、正典有效期和来源证明留在业务层，而不是混入 CRDT 历史。[Yjs 文档更新](https://docs.yjs.dev/api/document-updates) · [Y.Text](https://docs.yjs.dev/api/shared-types/y.text)
- 非并发远端状态按版本向量应用，旧包不覆盖新状态；同一密文哈希的包直接幂等返回；
- 正文并发自动合并并生成 `merge` 版本和 `sync_merge` 来源事件；
- 正典并发、删除/编辑必须由作者选择本机或接力包版本；
- 来源链只允许严格前缀追加。分叉建立 `provenance_fork`，只能保留本机链或知悉远端分叉，禁止静默重写成伪连续历史。

## 4. 可见工作流

- 四个主工作台保持“写作、剧情、正典、交付”，接力作为交付台二级工具，避免顶层导航继续膨胀；
- 未初始化项目显示设备命名与工程实验免责声明；
- 初始化后恢复短语只在一次性弹窗中显示，正文页只保留密码输入框；
- 可导出 `.bbd-sync`、导入前解密预检、显示对象数量并应用；
- 冲突中心用作者可读摘要呈现本机/接力包版本向量与决定按钮；
- “五项演练”不读取当前书稿，验证密文、错误短语、乱序收敛、缺块和并发向量；
- 书架提供“接力恢复”，支持空设备先预检再创建新 device ID 的副本。

## 8. 未关闭的外部门与限制

- 尚未部署账号、域名、中继服务或对象存储；自动上传、设备 ACK、吊销、密钥轮换、配额和删除 SLA 未实现；

- 当前恢复短语没有服务器后门；所有已解锁设备和短语同时丢失时，密文不可恢复；
- 中转方虽然看不到内容明文，仍能观察时间、大小、设备名称/ID和版本向量等元数据；
- 已解锁本机恶意软件、屏幕录制和作者主动泄露短语不在协议保护范围；
- Apple Developer ID、公证、Windows 构建与凭据库、跨地区合规、安全审计和隐私协议仍未完成；
- 真实种子作者留存、同步冲突处理率和 Pro 付费意愿仍须外部验证。
