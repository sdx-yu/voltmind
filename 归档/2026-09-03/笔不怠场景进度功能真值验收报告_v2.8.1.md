# 笔不怠场景进度功能真值验收报告 v2.8.1

## 结论

2.8.1 已完成场景进度工作流、场景状态卡和表单对齐规范的实现。普通进度不再混入“已完成／已发布”，完成状态只能由真实完成动作产生；终态正文发生实际修改后会自动回到“修订中”。

## 本次范围

- 将想法、计划、草稿、修订中定义为可直接切换的写作过程状态；
- 将已完成改为“完成本场景并提取事实”动作的结果；
- 保留已发布作为历史数据兼容状态，不伪造尚不存在的发布功能；
- 终态正文变更时自动进入修订，重复保存相同内容不改变状态；
- 同步和备份导入保留原有终态；
- 编辑器保存接口返回最新节点，使书稿树、标题区和右侧检查器即时同步状态；
- 重排场景状态卡，并统一多列表单的顶对齐、帮助文案和可选标识布局。

## 自动化覆盖

- 数据库：终态相同内容保持、不同内容进入修订；
- API：禁止通用接口伪造终态、完成动作、重复完成冲突、保存响应状态；
- 同步／备份：恢复后仍保留已完成；
- 组件：普通状态选项、完成动作、终态展示和进入修订；
- 真实浏览器：完成场景后修改正文，界面自动恢复“修订中”；
- 视觉回归：编辑器纸张视图、场景状态卡和多列表单对齐。

## 工程验收

- UI 基础门通过：24 个基础组件槽位、46 个语义色彩变量、3 套主题、3 档密度，原生选择器和裸必填字段均为 0；
- UI 质量与三主题 10 组关键对比度门通过，最小字号 12px；
- TypeScript 客户端与服务端类型检查通过；
- Vitest：55 个测试文件、230 项单元／集成测试全部通过；
- Vite 生产构建通过，共转换 2262 个模块；
- Playwright：13 项真实浏览器验收全部通过，包含状态工作流、表单对齐、视觉回归、WCAG、键盘、中文输入法、200% 回流、触控、响应式和二十万字性能门；
- 性能门修正了测试计时起点：先确认书架项目按钮可见，再测量打开大稿，8 秒阈值未放宽；
- Git 提交与安装包：待桌面交付记录。

## 产品边界

- “已发布”目前仅兼容历史数据；没有真实发布渠道、发布记录或撤回流程，因此不提供新增入口。
- 完成场景会提取事实并运行连续性检查，但不会伪称生成独立快照。
- 本次发布仍是内部测试交付；macOS 正式签名、公证及 Windows 正式代码签名仍需外部证书条件。
