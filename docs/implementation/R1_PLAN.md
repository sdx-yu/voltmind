# R1 真实作者验证与公开发布门（1.4.0）

状态：R1-A 本机验证基础设施已通过并归档；R1-B 受控种子验证等待真实作者与研究负责人，R1 公开发布保持 NO-GO。

V2-V 完成后，原始调研方案中的 MVP、V1 与 V2 本地可闭环能力均已落地。下一阶段不再继续堆功能，转向验证北极星闭环是否真的让长篇作者减少翻资料、返工和穿帮，并补齐公开发布所需的跨平台、安全与分发证据。

## 目标

用真实长篇项目和真实作者验证“写完一章—发现变化—作者确认—正典推进—下一章获得正确上下文”的价值，同时把内部可运行包推进到可公开分发的发布候选。

## 实施范围

1. 招募 5–10 名种子作者，签署明确的数据处理与反馈同意，使用真实或经授权的长篇项目完成四周试用；
2. 记录首次价值时间、每章候选确认率、误报/漏报、返工时间、恢复成功率、周留存和再次使用意愿；正文不进入遥测，研究数据采用最小披露；
3. macOS Developer ID 签名与 Apple 公证；Windows x64 构建、签名、安装/卸载、中文输入法和恢复矩阵；
4. 真实 360/390/430px 移动设备、断网/弱网、PWA 更新与加密接力演练；
5. 对视觉 Provider、模板生态和在线协作分别做版权、审核、费用、隐私和威胁评审，未通过前保持关闭；
6. 建立崩溃/支持流程、版本回滚、发布说明、签名校验和公开下载完整性验证。

## 验收门

- 至少 5 名目标作者完成两周、至少 3 名完成四周；
- 北极星闭环有可追溯任务证据，关键误报和数据丢失为零或有明确修复；
- macOS 公证与 Windows 签名安装包在目标系统矩阵通过；
- 数据恢复、升级回滚和支持演练通过；
- 隐私说明、版权边界和第三方条款与实际部署一致。

## 外部门

Developer ID、Windows 代码签名证书、真实招募、真实设备、分发账号和可能的图像供应商合同均需用户或组织提供。缺少这些条件时可以完成准备工作，但 R1 状态只能是“等待外部验证”，不能记为工程通过。

## R1-A 本机准备

1.4.0 已完成 [真实验证基础设施](R1A_PLAN.md)：固定知情同意、匿名参与码、无正文任务证据、`bbd-research-v1` 完整性链、`bbd-support-v1` 诊断和发布门看板。该阶段只证明研究工具可用，不产生任何真实作者、留存、公证或跨平台通过结论。证据见 [R1-A 验收报告](../../归档/2026-08-27/笔不怠R1-A真实验证基础设施验收报告_v1.4.0.md)。
