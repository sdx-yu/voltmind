# UI-F 表单与浮层统一计划（2.2.0）

## 背景

UI-A～UI-E 已统一页面骨架、主题和质量门，但业务页面仍大量使用系统原生 `select`。在 macOS 上展开后会出现不可控的系统蓝色、高行高和宽大浮窗；正典搜索区还存在旧容器与新字段组件叠加，形成双层边框和不一致背景。

## 目标

1. 选择器的触发器、浮层、选中态、禁用态和滚动行为全部服从笔不怠设计变量。
2. 搜索框采用单层输入结构，图标、清空动作、背景和焦点反馈统一。
3. 输入、选择、搜索和文本域共享控件表面语义，不再直接借用纸张或下沉背景。
4. 业务组件不再新增原生 `<select>`，并通过静态门阻止回退。
5. 保持鼠标、键盘、触控和三主题可用，不改变业务数据与 API 契约。

## 实施范围

- 新增 `SelectControl`、升级 `SelectField`，基于 Radix Select 提供 Portal、碰撞避让、视口限高、滚动、键盘与焦点管理。
- 新增 `SearchField`，把搜索图标、输入和显式清空按钮组合成单一控件表面。
- 新增 `surface-control`、hover、disabled 及菜单行高/最大高度语义变量，覆盖宣纸、夜间、高对比和三种密度。
- 迁移检查器、正典库以及交付、规划、审阅、研究、移动、设置等业务页面的全部原生选择器。
- 清理正典搜索旧样式冲突，并更新页面局部尺寸选择器。
- 扩展组件测试、业务交互测试、静态扫描和 Playwright 视觉基线。

## 完成定义

- `src/components` 中原生 `<select>` 数量为 0；
- 选择器支持 Enter/方向键/Escape，选择后焦点返回触发器；
- 浮层宽度跟随触发器，最大宽度和高度受视口约束；
- 搜索框无双层边框，触控密度下输入本体和按钮均不小于 44px；
- UI 基础门、三主题对比度、TypeScript、Vitest、生产构建、Playwright 与 `cargo check` 全部通过；
- 检查器选择浮层、正典搜索区和组件展厅选择浮层形成稳定视觉证据。

## 非目标

- 本阶段不改变表单业务字段、保存逻辑或服务端契约；
- 不实现可输入下拉、多选、远程搜索或超大数据虚拟列表；这些能力应在出现明确业务需求后独立设计。
