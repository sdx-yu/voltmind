# bbd-review-v1 离线审阅协议与威胁模型

状态：V2-R 1.0.0 冻结。

## 设计目标

`bbd-review-v1` 是双向、离线、最小授权的审阅接力协议。作者导出 assignment，审阅者在隔离副本中产生 feedback，再导出 response。它不提供账号、云权限、在线邀请或实时协作，也不让审阅者直接修改作者数据库。

## 角色能力矩阵

| 能力 | Editor | Beta Reader | Co-Writer |
|---|---:|---:|---:|
| 阅读作者选择的场景 | 是 | 是 | 是 |
| 段落级评论 | 是 | 是 | 是 |
| 局部替换建议 | 是 | 否 | 是 |
| 扩大场景范围 | 否 | 否 | 否 |
| 修改正文、正典或来源链 | 否 | 否 | 否 |
| 代替作者接受意见 | 否 | 否 | 否 |

作者逐条作出 accepted、rejected 或 deferred 决定。只有 accepted 的 suggestion 会生成正文新版本与 `review_suggestion_accepted` 来源事件。

## 外层信封

信封只包含协议路由与密码学字段：`format`、`protocolVersion`、`mode`、随机 `packageId`、`sessionId`、加盐项目指纹、scrypt 盐与密钥校验值、AES-GCM nonce/authTag、密文 SHA-256 和创建时间。项目标题、审阅者、角色、场景标题、正文、意见均在密文内。

- 恢复短语：192 bit 随机值，按 4 个十六进制字符分组，仅创建时显示；
- KDF：scrypt，N=32768、r=8、p=1，输出 256 bit；
- 加密：AES-256-GCM，随机 96 bit nonce；
- AAD：格式、版本、模式、包 ID、会话 ID、项目指纹与创建时间；
- 限制：最多 100 个场景，任务明文载荷最多 5 MiB，信封密文最多 10 MiB。

恢复短语必须经另一条安全渠道传递。短语不进入任务包、普通项目备份、日志或来源事件。

## 载荷

assignment 包含冻结的会话元数据和场景快照。每个场景带正文 SHA-256；可选来源信息仅为最近版本的来源标签，不含提示词、密钥或完整来源事件链。

response 只能包含同一会话、同一授权场景中的 comment 或 suggestion。反馈 ID 不可变；重复载荷幂等，同 ID 异载荷阻断。回应导入前复核项目指纹、角色、审阅者和完整有序场景列表。

## 段落锚点

锚点保存段落序号、段落 SHA-256、段内起止偏移、引用原文及前后各最多 24 字上下文。

- exact：原段落哈希和引用偏移均一致；
- candidate：原位已变化，但全文中只有一个同时满足引用和上下文的位置；
- lost：无唯一可信位置，不自动猜测。

失效 suggestion 不可自动接受。candidate 仍需作者显式点击采纳，并再次核对当前位置原文与 suggestion 的 originalText 一致。

## 威胁边界

已覆盖：错误短语、信封/密文篡改、跨项目回应、角色提升、场景越界、过期、过大载荷、重复导入和 ID 碰撞。

不覆盖：终端已被恶意软件控制、恢复短语与包经同一失陷渠道泄露、真实身份认证、撤回已经发出的离线副本、组织审计/数据驻留、网络中继可用性。离线包发出后无法技术撤回；敏感任务应设置最小场景范围并使用受信渠道。

## 备份互操作

普通 `bbd-backup-v2` 保存作者端会话、反馈、决定和历史场景快照，但排除盐、校验值、项目指纹与恢复短语。恢复后的会话标记为 `restored/archived`，只作历史查阅，不能继续导出原审阅包。
