# UI 贡献与新增页面准入规范

适用范围：2.1.0 之后所有界面新增、迁移和视觉调整。

## 1. 先选语义，再写页面

- 颜色只从 `src/ui/tokens.css` 的语义变量取值；功能 CSS 不新增裸颜色。需要新颜色时先证明现有 `surface`、`text`、`action`、`status` 语义无法表达，再补三主题映射和对比度组合。
- 字体、间距、圆角、阴影、控件高度和动效使用基础变量；关键文字不得低于 12px，常规正文不得低于 14px。
- 默认选择宣纸主题；夜间和高对比不是事后覆盖，而是同一语义的映射。

## 2. 组件优先级

1. 先复用 `src/ui/` 中的 Button、IconButton、字段、Tabs、卡片、列表、通知和 Radix 弹层；
2. 再用既有组件组合新业务结构；
3. 只有出现跨两个以上页面的稳定交互契约时才新增基础组件；
4. 禁止复制按钮、字段、弹层或焦点管理代码到业务页面。

图标按钮必须有可访问名称；状态不得只靠颜色；危险操作必须说明影响与恢复路径。

### 表单字段规范

- 常规弹窗和页面表单统一使用 `TextField`、`TextareaField`、`SelectField`、`SearchField`；紧凑型编辑器可保留无视觉标签控件，但必须提供可访问名称。
- 必填项使用 `required`：星号紧跟字段名、使用危险语义色且不单独占行；不得手写 `*`、括号“必填”或用占位文案代替标签。
- 可留空且用户容易误判的项使用 `optional`，统一在标签右侧显示“选填”；无需填写的默认配置项不强制堆叠“选填”。
- `description` 只解释用途或格式；`error` 就地替换说明并以危险语义呈现，控件同步设置 `aria-invalid` 与 `aria-describedby`。
- 有明确长度上限、内容可能较长的字段使用 `showCount`；计数与说明/错误并排，不能挤掉反馈文字。
- 标签、说明、计数和控件的禁用态同步；提交按钮禁用不能替代字段的必填语义。
- 标签必须通过 `htmlFor` 关联控件；不得使用会把 `.ui-field-label` 改成网格或块级的宽泛后代选择器。
- 多列字段必须顶部对齐：说明、计数或错误只占用所属字段下方空间，不得通过拉伸字段把相邻控件向下推；说明文字必须放在字段的 `description` / `error` 中，不得另写成破坏网格的兄弟节点。

## 3. 页面模板准入

新增页面必须属于以下一种根模板，并设置对应 `data-ui-template`：

- `editor`：正文为主、可选左右栏；
- `board`：卡片看板与时间/空间规划；
- `library`：对象列表、筛选与详情；
- `workflow`：两步以上的检查、决定、导出或恢复流程。

页面必须使用统一 AppShell、PageHeader、空/加载/失败状态；两步以上流程使用 `WorkflowSteps`，概览指标使用 `MetricStrip`。不得创造第五种局部应用壳。

## 4. 响应式与输入方式

- 必查 1440×900、1280×800、1024×768、430×932、390×844、360×800；宣纸和夜间主题都要通过；
- 200% 缩放下核心任务可完成，无关键内容截断或命中区重叠；
- 触控密度的交互目标至少 44×44px；
- 键盘顺序与视觉顺序一致，焦点清晰，弹层关闭后焦点回到触发控件；
- 全局快捷键必须忽略 `event.isComposing` / `keyCode === 229`，不得打断中文输入法候选；
- 动效遵循 `prefers-reduced-motion`。

## 5. 提交前证据

```bash
npm run check
```

该命令会执行：

- 设计基础防漂移；
- 三主题对比度、12px 字体下限、焦点/动效/触控静态门；
- TypeScript、Vitest 与生产构建；
- Chrome 视觉基线、Axe、键盘/IME/缩放、视口/PWA 矩阵与 20 万字性能旅程。

确有设计变更时先人工检查差异，再运行 `npm run e2e:update` 更新截图；不得仅为消除失败盲目刷新基线。新增关键页面至少补一项真实页面截图和一条核心旅程。

## 6. 外部环境声明

macOS 本机通过不等于 Windows、iOS 或 Android 通过。涉及系统字体、系统缩放、输入法、安装、离线、触控、签名或分发的改动，必须在对应真机/主机补证据；缺少条件时在验收报告中保留 BLOCKED/NO-GO，不使用模拟结果替代。
