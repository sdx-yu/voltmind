# V1-B 角色知识范围与 POV 泄密检查（0.4.0）

## 产品定义

系统记录“哪条秘密是什么、哪些词能识别它、哪个角色从哪个场景起知道”。当前场景设置 POV 后，如果正文明确使用了该秘密的识别词，而 POV 角色在此叙述位置尚未知情，系统只报告“泄密风险”并给出正文句、知识事实和知情起点；作者可以补录知情范围、改正文或设为例外。

## Must

- 项目可建立知识事实：名称、说明、识别词和首次对读者揭示场景；
- 知识事实可给一个或多个角色分配“从场景起知情”，保留来源场景、证据和备注；
- 删除采用软删除，不破坏历史分配；
- 检查按章/场景叙述顺序判断，不因倒叙故事时间误判角色知情；
- 未设置 POV 时不武断报告泄密；没有识别词命中时不报告；
- 风险必须带当前正文证据与冲突知识证据，并可复用现有“忽略一次”机制；
- 当前 POV 的已知/未知知识进入可见面板；AI 上下文只加入当前 POV 已知知识，不加入未知秘密；
- 离线备份完整保存知识事实和知情分配，旧备份仍可恢复；
- SQLite migration 升至 v4，升级前自动备份；版本升级为 0.4.0。

## 不做

- 用大模型自动判定角色内心是否真的使用了秘密；
- 自动把正文抽取结果写入知识范围；
- 读者知识曲线、群体/阵营共享知识和概率性传闻；
- 云端同步。

## 验收

1. 建立秘密“凶手是沈砚”，识别词包含“沈砚是凶手”；
2. POV 为林照、知情起点在场景 2，场景 1 正文命中时报告风险；
3. 场景 2 及之后不报告；切换无 POV 不报告；
4. 风险显示命中原句、秘密名称和知情起点；忽略后不重复；
5. AI 上下文在场景 1 不包含该秘密，在场景 2 包含；
6. 备份恢复后知识和分配不丢失；
7. 自动化、浏览器、桌面构建和启动全部通过并归档。
