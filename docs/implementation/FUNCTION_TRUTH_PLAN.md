# 2.2.1 功能真值修复计划

## 目标

让界面展示、可操作状态、运行结果与产品真实能力保持一致：能做的必须形成闭环，暂时不能做的必须禁用、解释或明确标为本地/演示能力。

## 修复范围

1. 桌面菜单与上下文命令：书架、独立工作台和项目内非适用页面都要响应；无法执行时给出明确原因，不再静默无效。
2. 场景树操作：空场景不提供拆分，末场景不提供向下合并；运行时继续校验正文与相邻场景。
3. 交付检查：人工规则从“启用开关”升级为绑定本次检查记录的持久化确认；自动检查与人工确认全部完成后才显示完成。
4. AI 状态：默认模型明确标为“不联网的固定演示候选”；真实 Provider 显示实际模型；连接失败使用错误语义，不再展示成功图标。
5. 本地接力与复制：统一说明为手动交换的加密文件能力，不暗示云同步；剪贴板失败必须提示手动替代路径。
6. 作者界面文案：移除阶段号、版本号等研发标签，保留任务语言和必要的发布门结论。

## 完成门

- 针对菜单路由、场景前置条件、交付人工确认、AI 演示状态与失败反馈新增回归测试；
- `npm run check` 全部通过；
- 使用隔离数据在真实浏览器中验证书架命令、场景禁用态、交付确认、AI 状态和设置说明；
- 浏览器控制台无新增错误；
- 版本统一升级为 2.2.1，并归档验收证据。

## 非范围

- 不把本地文件接力扩展为账号或云同步；
- 不把演示 AI 冒充真实模型；
- 不替代真实作者、Windows/移动真机、Developer ID 签名与公证等外部门。
