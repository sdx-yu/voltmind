# STORY-TIME V1 多时间体系方案

状态：已实施并随 2.8.0 内测版本发布。目标是让现代、古风、架空和时间未明的小说都能准确表达故事时间，同时避免把作者不确定的信息伪装成精确日期。

## 调研结论

- Aeon Timeline 将日历日期、相对日期、精度和不确定性拆开，并允许项目在没有完整日期时继续工作，因此本项目也不把公历设为必填前提：<https://www.aeontimeline.com/guides/story/outline-your-story>
- World Anvil 与 Campfire 都把自定义历法／纪年作为世界级配置，并把具体事件放到时间线上；本项目据此采用“作品默认体系 + 场景覆盖”，而不是每章重复配置一套历法：<https://www.worldanvil.com/learn/timelines>、<https://www.campfirewriting.com/calendar-creator>
- Library of Congress EDTF 明确区分准确、近似、不确定和区间表达；本项目 V1 先落地准确度标签与相对时间，后续再扩展范围日期：<https://www.loc.gov/standards/datetime/index.html>

## 产品定义

作品在“设置 → 故事时间”选择新场景的默认方式，已有场景不会被批量改写。每个场景可使用以下一种方式：

1. 现代日期：日期、可选时刻、精度；
2. 古风／自定义纪年：年号、纪年顺序、年、月、日、时辰；
3. 相对场景：相对某场之前／同时／之后若干小时、日、月、年或场；
4. 仅确定先后：只保存与锚点场景的前后关系，不杜撰具体间隔。

“作者显示文字”与内部结构坐标分开保存。例如作者可显示“承平十二年腊月廿三子时”，系统仍用纪年顺序、年月日和时辰判断先后。公历与架空纪年没有换算关系时不跨体系硬排序，退回叙事顺序。

## 真值与安全边界

- 旧的自由文本 `story_time` 保留，升级后不丢数据；新结构写入独立 JSON 字段。
- 相对时间锚点必须是同一作品内未删除的场景；拒绝自身引用、跨作品引用和循环链。
- 服务端重新生成可信显示值，不接受客户端伪造的显示文本与结构字段不一致。
- 正典状态、人物关系、倒叙检测和情节时间线优先使用结构化时间；混合时间体系不作伪比较。
- AI 上下文始终带入本场时间、时间类型和精度；未填写时明确要求模型不得自行推断。
- 备份恢复与加密接力包同时保留旧显示值和新结构字段。

## V1 验收标准

- 现代、古风、相对、仅排序四类表单均可保存、清除和再次编辑；
- 作品默认设置只影响新打开的空表单，不静默改写现有场景；
- 改元可通过纪年顺序正确排序；自定义显示不改变排序；
- 无效公历日期、无锚点、跨作品锚点和循环引用均被拒绝；
- 正典连续性、关系状态、AI 上下文、情节时间线、备份和同步均有回归测试；
- UI 基础、对比度、类型、单元／集成、生产构建和浏览器端到端门禁通过。

## 后续而非 V1

- 完整自定义月名、闰月、每月天数与多纪元换算规则；
- 日期区间、最早／最晚边界与可视化不确定带；
- 大规模时间图谱的拖拽编辑和矛盾解释链。
