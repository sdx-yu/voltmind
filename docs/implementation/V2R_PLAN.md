# V2-R 角色化审阅接力（1.0.0）

状态：本机工程通过（1.0.0）。对应原始调研 V2 的第一项“Editor、Beta Reader、Co-Writer 角色和段落级批注”，已闭环可审计的离线审阅包，没有伪造账号、在线权限或实时协作。验收证据见[归档报告](../../归档/2026-08-27/笔不怠V2-R角色化审阅接力验收报告_v1.0.0.md)。

## 目标

作者可选择书稿范围和审阅角色，导出不含项目写权限的加密审阅包；审阅者在独立副本中做段落级批注或建议，作者导入后逐条定位、接受、拒绝或搁置。任何外部意见都不能静默改写正文、正典或来源链。

## 实施范围

1. migration v10：审阅会话、不可变段落锚点、批注线程、建议补丁与作者决定；
2. Editor、Beta Reader、Co-Writer 三类能力矩阵：Beta Reader 只批注，Editor 可提交局部建议，Co-Writer 可提交指定范围建议；所有角色均无直接正典写权；
3. 以段落内容哈希、上下文摘要和偏移建立可重定位锚点；正文变化后分为精确、候选、失效，不猜测定位；
4. 冻结 `bbd-review-v1`：选择项目/章节/场景、是否包含来源摘要、有效期说明、加密封装、重复与乱序导入幂等；
5. 作者审阅台：按角色/场景/状态筛选，原文—建议 Diff，接受后生成新人工决定版本并追加来源事件；
6. 普通备份、恢复、删除与审阅包互操作；审阅身份和密钥材料不进入普通项目备份；
7. 自动化、真实浏览器、桌面发布和文档归档。

## 验收门

- 三角色越权矩阵全拒绝：Beta Reader 不能提交补丁，任何角色不能写正典、改来源链或扩大作者选择的范围；
- 同一审阅包重复/乱序导入不重复创建线程或决定；同 ID 异载荷明确阻断；
- 原文编辑后，锚点只在哈希/上下文满足阈值时给候选位置，否则进入“需人工定位”；
- 接受建议必须逐条显式确认，产生新版本和来源事件；拒绝/搁置不改变正文；
- 加密包错误短语、篡改、过大附件和跨项目导入失败且不产生部分数据；
- 桌面主流程和 0.9.0 移动收集、同步、备份全部回归通过。

## 明确不做

- 账号注册、云成员目录、邮件邀请、在线权限撤销或真实多人同时在线；
- 字符级实时合著、在线光标、语音视频、公共内容社区；
- 审阅者直接接受 AI 结果、直接改正典或绕过作者最终决定。

## 外部门

- 真实服务端鉴权、组织/成员生命周期、邀请滥用防护和数据驻留；
- 两个真实用户跨网络协作、通知 SLA、封禁/举报与审计合规；
- 真实编辑与 Beta Reader 的可用性和付费验证。
