# `r1b-cohort-v1` 受控种子证据协议

状态：R1-B 1.5.0 冻结。

## 输入与身份边界

输入只能是通过 `bbd-research-v1` 严格校验的包。负责人台不保存参与码本身，只保存 `SHA-256(r1b-cohort-v1 | participantCode)`；同意回执哈希用于阻断同一哈希身份静默换同意。匿名码与人工声明都不是密码学身份认证，负责人仍须在产品外保存访问受控的招募与同意证据。

## 人工声明

真实外部证据必须由研究负责人逐项声明：参与者属于目标长篇作者、不是团队/自动化重复样本、稿件已获授权、包来自真实任务。缺少任一项只能按 `engineering_fixture` 导入，且永不计入任何门禁。声明没有自由文本，避免姓名、联系方式或稿件内容进入本机研究库。

## 连续提交

首次提交保存包哈希、同意回执、事件哈希序列和计算后的有界摘要。后续提交必须：

1. 参与码哈希与同意回执不变；
2. 旧事件哈希序列是新序列的完整前缀；
3. 新序列至少多一个事件；相同链头视为幂等；
4. 任务、事件和声明进度重新计算后一致；
5. 已删除参与者的双哈希回执命中时拒绝重新导入。

负责人台不保存原始包 JSON、书名、正文、正典、项目/任务 ID 或 Prompt。原始离线包的访问控制、备份和删除由研究负责人在产品外执行。

## 周期与聚合

自然周按 UTC 周一划分。两周资格同时要求至少 2 个有完成任务的自然周桶和同意至最近完成任务跨度 ≥8 天；四周资格要求至少 4 个桶和跨度 ≥22 天。聚合只使用未过期的 `external_attested` 最新连续提交，工程夹具单独计数。

`bbd-cohort-v1` 导出只包含阈值、总量、分层数量、任务成功率、问题码计数、不可逆参与者哈希和完整性哈希。报告不证明招募真实性、独立人数、因果效果、付费意愿或公开发布资格。

## 删除与保留

首次真实导入必须设置 1–365 天保留期限。到期清除或退出删除会级联移除参与者和所有提交摘要，并写入 `SHA-256(r1b-cohort-deleted-v1 | participantCodeHash)` 回执、原因、删除数量和时间。回执用于阻断误重收，不可用于恢复原记录。
