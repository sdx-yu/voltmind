# R1-C 受控两周波次执行（1.6.0）

状态：R1-C 波次执行能力本机工程通过（1.6.0）。真实作者招募、真实时间流逝与研究结论仍为外部门，真实外部波次为 0。

## 目标

把 R1-B 的单包聚合升级为可审计的研究波次：负责人先冻结范围、分层配额、时间窗、支持/删除流程，再开放招募和执行；研究包只能归属类型相符的波次，异常只用固定码记录。工具提供执行证据，不发送邀请、不保存联系方式、不自动证明真人或把 R1 改为 GO。

## 范围

1. migration v16：`research_waves`、不可变 `research_wave_events`、有界 `research_wave_incidents`，参与者增加不可变 `wave_id`；
2. 波次分为 `external_controlled`（真实受控）和 `engineering_rehearsal`（工程演练），演练永不进入真实波次进度；
3. 外部波次目标人数 5–10，四个固定作者分层配额之和必须等于目标；起止窗口为 14–42 天；
4. 招募前必须逐项确认协议已审阅、产品外访问受控名册已建立、删除联系人已就绪、支持/恢复路径已演练；
5. 状态机：草稿 → 招募中 → 执行中 ↔ 暂停 → 复核中 → 已关闭；允许受控取消，禁止跳步；
6. 外部研究包只能归属外部波次，工程夹具只能归属演练波次；首次归属后不可静默换波次；
7. 固定异常码与级别，不提供姓名、自由文本、正文或联系方式字段；未解决严重异常阻断关闭；
8. 导出 `bbd-wave-kit-v1`，包含冻结协议、配额、窗口、参与者操作清单与删除/支持边界，不含名册或个性化邀请。

- 真实浏览器完成工程演练波次的创建、准备、开放与 NO-GO 核对；
- 全量回归、1.6.0 生产构建、桌面包与归档通过；
- 验收只声明“R1-C 波次执行能力工程通过”，真实波次状态仍为未开始。

## 不计数边界

- `engineering_rehearsal`、自动化、浏览器和开发者自测；
- 只有计划配额、截图、口头名单或未导入研究包的招募意向；
- 未归属外部波次、波次类型不符、时间窗不符或负责人声明不完整的包；
- 暂停、取消、过期、删除或事件链不连续记录；
- 工具生成的波次包、检查清单或聚合导出本身。
