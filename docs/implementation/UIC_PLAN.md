# UI-C 页面模板与核心工作台（1.9.0）

基线：[UI 统一规划与设计方案 v1.0](UI_SYSTEM_PLAN_V1.md)、[UI-A 设计基础](UIA_PLAN.md)、[UI-B 壳层与信息架构](UIB_PLAN.md)

状态：本机工程与真实浏览器验收通过（2026-08-28）。

## 目标

在不改变业务数据、编辑器技术栈和操作语义的前提下，建立页面骨架契约，并先迁移作者最常使用的写作、规划和正典三个工作台。

## 模板契约

- **Editor**：左侧对象导航、中央创作内容、右侧当前对象详情；侧栏按宽度逐级转为抽屉。
- **Board**：统一页头、视图切换和可滚动工作区，用于同一故事数据的多种规划视图。
- **Library**：左侧可搜索/筛选的对象列表与右侧详情；移动端在列表和详情之间单任务切换。
- **Workflow**：本阶段只冻结基础容器，修订、交付和长尾流程在 UI-D 迁移。

## 响应式规则

| 宽度 | Editor | Library / Board |
|---|---|---|
| ≥1280 | 左栏 + 正文 + 右栏 | 双栏详情 / 宽画布 |
| 1024–1279 | 左栏 + 正文，右栏抽屉 | 紧凑双栏 / 收紧留白 |
| 760–1023 | 正文，左右栏抽屉 | 紧凑双栏 / 收紧留白 |
| <760 | 单任务正文与抽屉 | 列表/详情单页切换 / 移动留白 |

抽屉使用成熟行为层，必须具备可访问标题、焦点约束、Esc 关闭和触发器焦点归还。

## 边界与下一阶段

UI-C 不改 API、数据库、同步协议和编辑器技术栈，也不伪造外部研究或发布证据。修订、交付、研究、恢复、审阅接力和同步冲突等 Workflow 页面内部迁移属于 **UI-D**；视觉回归、全量可访问性与跨平台代表矩阵属于 **UI-E**。
