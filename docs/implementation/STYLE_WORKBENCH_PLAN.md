# 文风工作台落地方案（STYLE-A～C）

状态：STYLE-A～C 已实施并通过本机工程验收
日期：2026-09-01
标语：笔耕不怠，写尽所思。

实施说明：最终实现遵循本方案的产品边界，但将数据结构收敛为 `project_voice_defaults`、`scene_voice_profiles`、`style_analysis_runs`、`character_voice_profiles` 和 `voice_preference_stats`，避免另建一套与既有场景继承链重复的 `style_profiles`。数据库当前为 schema v20；三阶段证据见同日归档的 2.4.0、2.5.0、2.6.0 验收报告。

## 1. 结论

文风切换、词穷补笔和“有思路但写不出来”不是三个孤立的 AI 按钮，而是一条高频创作闭环：

`选择本书文风 → 写作中局部找词/改写 → 用自然语言说明段落意图 → AI 按当前文风和正典给出候选 → 作者选择接受 → 保留来源与撤销能力`

建议将它定义为笔不怠下一条核心能力“文风工作台”，而不是通用润色功能。这里的“文风”不是某位名家的身份标签，而是一套作者和 AI 共同理解的分类语言。竞争差异不在于预设数量，而在于同时做到：

1. 文风是作品级、可继承、可临时覆盖的显式配置；
2. AI 生成同时受正典、POV、人物状态、伏笔和当前文风约束；
3. 所有结果都是候选，支持原位替换、差异查看、拒绝、撤销和来源留痕；
4. 市场风格被归纳为通用写作特征，作者样本只是可选校准材料，不是使用文风功能的前提；
5. 首版保持本地免费模型闭环，不产生 API 费用。

## 2. 市场调研与可借鉴模式

| 产品 | 已验证能力 | 可借鉴 | 笔不怠不照搬的部分 |
|---|---|---|---|
| Sudowrite | 作品级 Style、Match My Style、Rewrite、Describe、Write；风格会影响语气、词汇和句式 | “本书风格 + 当前任务”的持续生效；感官描写拆成可选建议 | 不把整段生成作为唯一入口，不让风格覆盖正典事实 |
| ProWritingAid | 选中句子后提供 Standard、Sensory、Shorten、Expand、Emotion 等模式，并一次给出多条建议；Sparks 可从笔记扩写 | 选区浮动入口、按创作意图命名、多个小候选 | 不堆叠二十多个入口；不把同义改写和剧情续写混为一类 |
| Grammarly | 从用户文本形成 Voice Profile，并在写作中按个人 voice 改写 | 作者自己的风格档案可持续复用，结果应可解释 | 不自动静默更新文风；小说项目间默认隔离 |
| Novelcrafter | Codex 进入 AI 上下文；可建立 prompt presets、persona 和跨项目记忆 | 风格配方与正典使用同一上下文解释机制；允许项目级默认和任务级覆盖 | 不把复杂 prompt 暴露给普通作者，不要求用户先学提示词工程 |
| 阅文作家助手 / 写作猫 | 中文创作中的查词、改写、润色和续写已成为明确场景 | 中文网文节奏、词汇辅助和随写随用是基本盘 | 不以平台发布和云账号为前提；不采集稿件训练 |

市场已证明单点需求成立，但仍有明显空位：把“可切换文风、小说正典、人物口吻、本地隐私和可验证接受”组合成一个连续写作工作流。这里是笔不怠最有机会建立差异的位置。

## 3. 当前项目基础与缺口

### 3.1 已有能力，可直接复用

- `style_samples` 已支持项目/系列样本、标题、原文、使用指导、隐私级别和启停；
- AI 上下文已包含当前场景、提及实体、人物档案、时态状态、当前关系、最近场景、伏笔、POV 已知事实和风格样本；
- AI 已有脑暴、续写、改写、冷读任务；
- 本地 Ollama、流式输出、预热、停止、分阶段超时和一次自适应重试已经完成；
- 候选 Diff、接受/拒绝/撤销、修订来源和 provenance 事件已经完成；
- Tiptap 3 已提供 React `BubbleMenu`，可在选区旁实现原位 AI 操作，不必自行维护浮层坐标系统。

### 3.2 当前缺口

1. 风格只有“原文样本”，没有可读、可组合的文风配方；
2. 样本入口位于系列正典页，写作中看不到当前实际生效文风，也不能快速切换；
3. 当前改写使用整个场景作为原文，编辑器没有向 AI 传递精确选区；
4. AI 接受动作统一在光标处追加，改写任务尚不能安全替换原选区；
5. 续写、改写只有通用 prompt，没有任务级文风强度、输出形态和事实保护合同；
6. 风格样本在本地上下文裁剪队列末尾，小模型上下文紧张时可能失去文风；
7. 没有“词语灵感”和“思路成文”两个符合作者心智的入口；
8. 没有文风质量基准，无法判断“更像当前作品”是否真实成立。

因此，下一阶段应扩展现有链路，不新建第二套 AI 系统。

## 4. 产品定义

### 4.1 三层文风

文风按以下顺序解析，越靠后优先级越高：

`系列基线（可选） → 本书基础文风 → 章节覆盖 → 场景覆盖 → 本次临时要求`

首版必须支持本书基础文风和场景临时覆盖；章节持久覆盖可在数据层就绪、界面后置。AI 面板显示一枚“当前文风胶囊”，展开后能看到每一层来自哪里，避免隐性状态。

题材与文风分开保存：悬疑、仙侠、都市是题材；冷峻、轻快、克制、诗性才是文风。题材可以推荐起始配方，但不能直接决定文风。

### 4.2 文风分类语言

文风不能只做成一长串互斥预设，否则会出现“接近但不完全符合”的选择困难。系统采用四层分类，并把最终选择编译为 AI 可执行的结构化文风规格：

1. **主风格**：决定整体声线，一次选一个；
2. **表达维度**：决定句式、词汇、叙事和描写方式，可组合；
3. **场景意图**：说明这一段要带给读者什么感受；
4. **强度**：轻微、标准、鲜明，决定 AI 调整幅度。

主风格首版归为 8 类：

| 主风格 | AI 应理解的核心特征 | 常见使用场景 |
|---|---|---|
| 自然流畅 | 清楚、顺滑、不过度修饰，优先准确传达 | 通用叙事、初稿整理 |
| 冷峻克制 | 低情绪直述、少评价、留白、动作承担情绪 | 悬疑、现实、压迫场景 |
| 明快轻盈 | 节奏轻、句式灵活、低阅读负担 | 日常、青春、轻喜剧 |
| 细腻抒情 | 贴近感受、重细节与内心变化、节奏偏缓 | 情感、成长、关系变化 |
| 硬朗利落 | 动词优先、短句、少形容、因果直接 | 动作、战争、冒险 |
| 古雅含蓄 | 典雅词汇、克制表达、避免现代口语穿帮 | 历史、武侠、仙侠 |
| 诡谲氛围 | 感官错位、不确定性、信息延迟、避免直接解释 | 惊悚、怪谈、悬疑 |
| 诗性意象 | 意象关联、节奏感和含蓄比喻，但保持可读 | 文学、梦境、氛围段落 |

主风格不是题材模板，也不是固定 prompt。每个配方继续由以下可解释维度构成：

- 句式节奏：短促 / 均衡 / 绵长；
- 叙事距离：贴近人物 / 中等 / 远观；
- 情绪温度：克制 / 平衡 / 强烈；
- 行文速度：舒缓 / 平衡 / 快速；
- 意象密度：低 / 中 / 高；
- 感官偏好：视觉、声音、触觉、嗅觉、味觉；
- 对话占比：低 / 中 / 高；
- 词汇质地：朴素、现代口语、典雅、古意、硬朗；
- 心理描写：少 / 中 / 深；
- 正向规则：希望出现的表达习惯；
- 负向规则：禁用词、陈词滥调、过度解释、过度修辞等。

场景意图独立于主风格，可选“推进冲突、营造压迫、放松节奏、深化情感、制造悬念、突出画面、强化对白、保持客观”等。比如同样是“古雅含蓄”，打斗场景可以叠加“快速 + 动作驱动”，告别场景可以叠加“舒缓 + 留白 + 情绪克制”。

最终展示和传给 AI 的不是模糊名称，而是类似下面的文风规格：

```json
{
  "baseFamily": "冷峻克制",
  "strength": "标准",
  "rhythm": { "sentence": "偏短", "pace": "快速" },
  "narration": { "distance": "贴近人物", "interiority": "中等" },
  "diction": { "register": "现代朴素", "ornament": "低" },
  "imagery": { "density": "低", "sensoryFocus": ["声音", "触觉"] },
  "sceneIntent": ["营造压迫", "推进冲突"],
  "prefer": ["用动作呈现情绪", "保留未解释信息"],
  "avoid": ["华丽堆词", "直接说明人物害怕", "新增事实"]
}
```

服务端把这份规格编译成简短、明确、互不矛盾的生成规则。用户界面只显示自然语言摘要，例如：

`冷峻克制 · 偏短句 · 快节奏 · 低修辞 · 贴近人物 · 营造压迫`

如果组合产生冲突，例如同时选择“极快节奏”和“高密度细腻心理”，系统不静默拼接 prompt，而是提示优先其中一个，或把两者降为中等。

STYLE-A 内置上述 8 个主风格及一组经过约束的表达维度。题材可以推荐组合，例如悬疑默认推荐“冷峻克制 + 信息延迟 + 中快节奏”，但作者可以完全修改。全部使用创作特征命名，不使用作者姓名。

作者可以在配方上叠加少量修饰：短句、对话驱动、增强画面、增强五感、心理深入、减少词藻、增强张力、增加留白。配方和修饰最终都可见、可撤销。作者样本只用于进一步校准“这些维度在我的作品里具体长什么样”，没有样本时文风分类仍能完整工作。

### 4.3 三个高频入口

#### A. 写作中切换文风

- AI 面板顶部显示 `当前文风：冷峻悬疑 · 短句 · 克制`；
- 点击后最多两次操作即可切换本场景文风；
- 默认只对当前场景临时生效；“设为本书默认”必须是显式动作；
- 切换不自动改动已有正文，只影响后续 AI 候选。

#### B. 选区灵感与改写

选中正文后显示紧凑浮动条：

- 词语灵感；
- 换种说法；
- 增加画面；
- 补充五感；
- 加强动作；
- 补充心理；
- 更克制；
- 按当前文风润色。

一级只显示 4 个高频项和“更多”，避免遮挡正文。词语灵感返回词组/搭配/动作/感官建议，不生成大段正文；改写默认返回 3 个短候选，点击候选后原位替换选区。

#### C. 思路成文

用户输入自然语言意图，例如“进入矿洞，看到不属于这个时代的机械结构，暂时不揭底，压抑、少修辞”。系统按当前文风和正典生成一个 300～500 字候选，再提供“换一种：稳妥承接 / 氛围深化 / 冲突推进”。

本地 4B 模型首轮只生成一个正文候选，而不是一次并发生成三大段；这样能缩短等待、降低超时。用户需要时再生成另一种方向。候选默认插入光标处，插入前可预览并逐句取消。

## 5. 关键交互与真值规则

### 5.1 原位改写必须绑定原文版本

选区任务保存：

`nodeId, sourceRevisionId, sourceContentHash, from, to, originalText, contextBefore, contextAfter`

接受候选前重新验证当前正文：

1. 内容哈希未变且选区原文一致：允许替换；
2. 正文变化但前后文指纹唯一匹配：提示已重新定位，允许替换；
3. 无法唯一定位：拒绝自动替换，保留候选供复制或重新生成。

这可以复用现有审阅锚点与正文 mention 修复思路，不能继续使用“统一在末尾插入”的接受方式。

### 5.2 候选形态

- 词语灵感：6～10 个短建议，按“动作 / 感官 / 搭配 / 比喻”分组；
- 句子改写：3 个互斥候选，一次只接受一个；
- 段落改写：1 个主候选 + 2 个“换一种”方向，避免小模型一次输出过长；
- 思路成文：1 个正文候选，逐句选择；
- 续写：保持现有逐句选择，但显示当前文风和使用的正典范围。

“候选方向”和“候选内部句子”不得混用复选语义。候选之间是单选；候选内部可按句取舍。

### 5.3 事实保护

生成 prompt 固定声明：不改变既有事实、人物身份、POV、时态和已建立关系；不提前揭露 POV 未知事实；不擅自回收伏笔。接受前运行轻量规则检查：

- 新增未识别专名；
- 人物称谓/别名冲突；
- POV 或时态明显变化；
- 与有效人物状态、关系、知识授权冲突；
- 与风格样本出现过长连续重合。

命中风险时不自动阻断查看，但“接受”按钮旁显示风险说明。高置信正典冲突必须二次确认。

## 6. 数据模型与接口

### 6.1 migration v18（STYLE-A）

新增 `style_profiles`：

```text
id, project_id, series_id, name, source_kind,
genre_tags_json, dimensions_json,
positive_rules_json, negative_rules_json,
is_default, created_at, updated_at, deleted_at
```

`source_kind`：`builtin_copy | custom | distilled`。内置配方在用户首次采用时复制为项目数据，后续版本升级不能静默改变用户已使用的配方。

新增 `style_profile_samples`：

```text
profile_id, sample_id, purpose, weight, created_at
```

新增 `style_bindings`：

```text
id, project_id, scope_type, scope_id, profile_id,
modifiers_json, created_at, updated_at
```

`scope_type`：`project | chapter | scene`。同一作用域只有一个当前绑定。临时单次要求不入绑定表，只写入 AI 任务元数据。

给 `style_samples` 增加独立的 `ai_use_policy`：

- `never`：只存档，不进入任何 AI；
- `local_only`：只允许本机模型读取；
- `allowed_provider`：未来作者显式允许配置的 Provider 使用。

现有 `local_private` 仍保持“任何 AI 都不读取”的真值，不在迁移中偷偷改变含义。

### 6.2 类型和 API

新增共享类型：`StyleProfile`、`StyleDimensions`、`StyleBinding`、`EffectiveStyle`、`TextSelectionAnchor`、`AiCandidateKind`。

新增接口：

- `GET/POST /api/projects/:id/style-profiles`
- `PATCH/DELETE /api/style-profiles/:id`
- `PUT /api/projects/:id/style-bindings/:scopeType/:scopeId`
- `GET /api/projects/:id/effective-style?nodeId=...`
- `POST /api/ai/style-preview`（仅把配方编译为可读预览，不调用模型）

AI 任务扩展为：

- `word_inspiration`
- `style_rewrite`
- `idea_to_prose`

请求中可带 `selectionAnchor` 和 `styleOverride`；服务端必须重新解析有效文风和选区，不信任客户端直接传入的 prompt 文本。

### 6.3 备份、同步与来源

- 普通备份和加密接力携带 profile、sample link 和 binding；恢复时全部重映射；
- 项目风格不得跨项目串读；系列配方继续遵循成员关系；
- AI 任务记录 `style_profile_id`、`effective_style_hash`、`selection_hash`、任务类型、模型和 token，不记录完整 prompt；
- 接受事件记录“插入”或“替换”、来源任务和源修订；拒绝与撤销继续进入 provenance 链。

## 7. AI 上下文与生成链路

### 7.1 编译顺序

`用户任务 → 精确选区/段落意图 → 有效文风摘要 → 必须遵守的正典 → 局部上下文 → 最多两个授权样本摘录 → 输出合同`

有效文风先编译成不超过 250 token 的规则摘要，优先级高于原始样本。原始样本只用于节奏和表达参考，不复用专名与独特句子。

STYLE-A 将当前通用 `buildContext` 改为任务级预算：

- 词语灵感：选区和前后文优先，通常不加载完整伏笔与历史；
- 改写：选区、有效文风、POV/人物状态优先；
- 思路成文/续写：当前场景、正典、最近历史、有效文风优先；
- 冷读：正文优先，不让风格规则影响读者判断。

不能再按固定数组顺序把风格排在末尾后统一裁剪。

### 7.2 输出合同

小模型容易产生格式漂移。新增任务使用 JSON Lines 或带稳定分隔符的最小结构，不要求复杂嵌套 JSON；服务端以 Zod 验证，失败后进行一次本地格式修复，仍失败则把原始输出作为一个候选展示，不写正文。

改写质量按三维检查：

1. 文风强度：目标特征是否发生；
2. 内容保持：原意和事实是否保持；
3. 自然度：是否像正常中文正文。

这是文本风格迁移研究中最稳定的三个基础维度；笔不怠额外增加“正典一致性”和“可采用性”。

### 7.3 本地模型策略

- 继续默认 `qwen3.5:4b`，负责找词、短句改写、短段续写和文风摘要；
- 设置中增加“当前设备推荐”：4B 为轻量，9B 为质量优先；两者都通过本机 Ollama，API 费用为 0；
- 不因模型标称长上下文而把整书塞入请求，维持当前受控上下文和任务级裁剪；
- 先用固定中文样例跑质量基准，再决定是否推荐 9B，不以参数量直接冒充质量结论；
- STYLE-A 不做 LoRA、微调或自动训练。文风配方 + 授权短样本 + 正典约束足以验证需求。

## 8. 分阶段实施

### STYLE-A / 2.4.0：高频闭环

目标：作者能在写作页看见并切换当前文风，完成精确选区灵感/改写和思路成文。

1. migration v18、类型、CRUD、作用域解析、备份/恢复；
2. 8 个内置配方和文风编辑器；
3. AI 面板当前文风胶囊与场景临时切换；
4. Tiptap 选区浮动条、选区锚点和安全替换；
5. `word_inspiration`、`style_rewrite`、`idea_to_prose` prompt 与候选 UI；
6. 任务级上下文预算、风格哈希和来源事件；
7. 正典风险提示、样本连续重合提示；
8. 自动化、真实浏览器、桌面回归和验收归档。

### STYLE-B / 2.5.0：作者文风 DNA

目标：从作者明确授权的自有样本中生成可检查的配方。

1. 每份建议 300～800 字，总计 1,500～3,000 字；
2. 句长、段长、对话比例、标点节奏等由确定性统计计算；
3. 意象、叙事距离、情绪温度等由本地模型给出结构化建议；
4. 分析结果先预览、逐项确认，再保存为 `distilled` profile；
5. 展示每个结论来自哪些样本，不自动覆盖现有配方；
6. 提供“样本不足”和“样本风格互相冲突”提示。

### STYLE-C / 2.6.0：一致性与人物口吻

目标：发现长篇中的文风漂移，并区分叙述者文风和人物对白口吻。

1. 章节文风一致性检查，只报告证据，不自动重写；
2. 人物对白口吻规则，绑定正典人物；
3. 接受/拒绝行为形成本地偏好统计，必须允许查看和清空；
4. 项目级文风对比报告，不做单一“文学分数”；
5. 经真实作者验证后再决定是否增加更多市场配方。

## 9. STYLE-A 验收标准

### 9.1 功能与数据

1. 新建、修改、复制、停用文风配方，重启后保持一致；
2. 本书文风和场景文风按优先级解析，AI 胶囊解释来源；
3. 切换文风最多两次点击，不改动已有正文；
4. 选中词、句、段后浮动条可用，Esc 关闭，键盘能完整操作；
5. 选区改写只替换目标文本；正文变化或锚点失效时不能误替换；
6. 思路成文插入光标位置，接受、拒绝、撤销均有来源事件；
7. `never/local_only/allowed_provider` 策略严格执行，零费用模式没有外网请求；
8. 备份恢复后配方、绑定、样本关联和任务来源一致；
9. 样本或正典上下文不会跨项目泄漏；
10. 旧数据库升级前自动备份，v17→v18 迁移可重复验证。

### 9.2 质量基准

建立 48 条不含真实作者受版权保护文本的中文测试集：

`8 种文风 × 3 类任务（找词/改写/思路成文）× 2 条内容`

人工盲评 1～5 分，工程候选门：

- 内容保持平均 ≥ 4.2；
- 自然度平均 ≥ 4.0；
- 文风可辨识度平均 ≥ 3.8；
- 改写任务中明确事实、POV 和时态保持率 ≥ 95%；
- 任何候选都不能未经作者接受写入正文；
- 授权样本连续重合达到 20 个汉字时必须提示来源，不能静默接受。

参考 Apple Silicon 16GB、模型已预热的本地环境：找词首 token P95 ≤ 12 秒，短改写/思路成文首 token P95 ≤ 20 秒；完整候选超过 90 秒视为失败并提供可操作提示。最终报告必须记录设备与模型，不能把单机结果泛化为所有设备。

### 9.3 UI 与回归

- 390、768、1024、1440、1920 宽度不遮挡正文和系统窗口；
- 浮动条、候选卡、文风选择器使用现有 UI token 和 Radix/Tiptap 组件；
- 200% 缩放可回流，焦点可见，触控目标不小于 44px；
- 现有脑暴、续写、改写、冷读、正典识别、自动保存和撤销流程不得回归；
- `npm run check` 全部通过，并增加真实浏览器的“选中 → 改写 → 正文变化后阻断误替换 → 重新生成 → 接受 → 撤销”主流程。

### 9.4 产品验证门（不能由自动化冒充）

邀请至少 5 位目标小说作者，每位完成至少 20 次真实任务。进入 STYLE-B 前建议满足：

- 至少 60% 的参与者每个写作会话主动使用一次文风入口；
- 候选完整或部分采用率 ≥ 35%；
- “切换文风容易理解”平均 ≥ 4/5；
- “结果仍像我的作品而非通用 AI 文”平均 ≥ 3.8/5；
- 没有作者报告正文被误覆盖或样本未经授权进入 AI。

工程可以完成 2.4.0，但真实作者门未执行前只能标记“工程通过、产品验证待外部”，不能宣称需求已被市场验证。

## 10. 风险与边界

### 10.1 版权与模仿

- 不抓取市场小说正文建立预设；市场调研只提炼创作维度和通用技法；
- 不提供“像某位在世作者”按钮、标签或营销文案；
- 用户添加样本时确认拥有使用权，并能随时停用、删除；
- 输出与样本出现较长连续重合时提示，不保证替代专业版权审查；
- 产品文案使用“参考节奏/结构/语气”，不宣称复制作者身份或独特声音。

### 10.2 小模型质量

- 4B 适合高频、短范围任务，不承诺一次生成整章仍保持稳定文风；
- 首版限制选区和输出长度，复杂生成拆成按需重试；
- 结构化失败退化为普通候选，不写正典、不写正文；
- 是否推荐 9B 以本地实测和用户设备为准。

### 10.3 交互膨胀

- 写作页只展示当前文风、四个高频选区动作和一个“更多”；
- 复杂维度编辑放入文风工作台，不塞进浮动条；
- 题材、文风、人物口吻分层，避免所有偏好堆进同一选择框。

## 11. 明确不做

- STYLE-A 不微调模型、不训练 LoRA、不下载或抓取市场小说；
- 不自动重写整本书；
- 不自动学习并覆盖作者文风；
- 不以作者姓名提供模仿；
- 不增加付费云模型、账号、额度或订阅；
- 不把 AI 生成内容自动写入正典；
- 不在没有真实作者证据时无限增加预设数量。
