# V1-A 剧情控制层实施计划（0.3.0）

基线：[线上调研与产品方案](../../码字软件线上调研与产品方案.md) · [里程碑与验收计划](../../归档/2026-08-26/笔不怠里程碑与验收计划_v1.0.md)

## 为什么选择这一阶段

存档中的 V1 候选依次包含多设备加密同步、Plot Grid 与双时间线、伏笔生命周期。同步需要账户、云端、密钥恢复、冲突协议和真实多设备环境，当前无法仅靠本地版本完成可信闭环；双时间线与伏笔状态机则直接对应已调研的两个高价值缺口，并能复用现有场景、故事时间和可解释 AI 上下文。

因此 0.3.0 选择一个可独立交付的垂直切片：让作者能够比较“读者看到的顺序”和“故事实际发生顺序”，并把伏笔从备注升级为带正文证据的生命周期。

## 范围

### Must

- 品牌 slogan 在首屏、网页元信息、桌面物料和文档中统一为“笔耕不怠，写尽所思。”；
- 剧情台可在叙述顺序、故事时间、伏笔看板之间切换；
- 故事时间按场景 `storyTime` 排序，未定时间明确置后，不猜测日期；
- 伏笔支持建立、强化、误导、回收四阶段，每次变化可关联场景、正文证据和作者备注；
- 服务端拒绝非法状态跳转和跨项目场景引用；
- 未回收伏笔进入交付提醒，但不得阻断导出；
- 未回收伏笔进入 AI 上下文胶囊，明确标注读取原因；
- 完整离线备份保存并恢复伏笔及事件链；旧版 `bbd-backup-v2` 仍可恢复；
- SQLite 升级前自动备份，schema migration 升至 v3。

### 本阶段不做

- 云端账户与多设备同步；
- 自由节点式因果图；
- 从正文自动写入伏笔（仍坚持作者确认后生效）；
- 平台规则包与多人协作。

## 验收清单

1. 新建项目后，在剧情台的两个时间视图中看到同一组场景；设置故事时间后排序可验证。
2. 建立一条高优先级伏笔并关联场景/证据，事件链首项为“建立”。
3. 将其强化或误导，再回收；每次事件均保留，非法跳转返回错误。
4. 未回收时交付台显示提醒，回收后提醒数下降；两种状态都可继续导出。
5. AI 上下文出现未回收伏笔，回收后不再出现。
6. 备份后恢复为新项目，伏笔状态、证据和事件数一致。
7. `npm run check`、桌面构建、真实浏览器主流程和控制台检查全部通过。

## 完成定义

- 自动化测试、类型检查、Web 构建通过；
- macOS Apple Silicon 桌面包可生成并启动；
- 浏览器按可访问名称完成主流程，页面无控制台错误；
- 验收结果归档，明确已通过项、已知限制与下一阶段建议。
