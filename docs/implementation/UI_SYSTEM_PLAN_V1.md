## 1. 结论

笔不怠不需要换一套“流行皮肤”，而需要建立一套能约束后续迭代的产品界面系统。

建议将统一方向定义为：

> **温润纸感，克制工具感；正文是主角，复杂能力按任务出现。**

保留现有暖米白、文人绿、朱砂点色、宋体内容标题的品牌辨识度；重做信息架构、界面骨架、密度规则和基础组件。最终形成：

- 一套稳定的应用壳层；
- 五个按作者任务划分的工作模式；
- 四种页面模板；
- 一套语义设计变量与组件库；
- 三档布局密度与完整的响应式规则；
- 浅色、夜间和高对比模式共用同一套语义；
- 可由自动化与人工共同验收的 UI 质量门。

这不是视觉重做，而是把已经完成的产品能力重新组织成一致、可学、可扩展的工作台。

## 2. 调研方法与样本

本轮调研分为两条线：

1. 检查笔不怠 1.6.0 的书架、写作、剧情、正典、交付以及长尾工作台；
2. 对照成熟写作产品和权威设计系统，提取可复用的交互原则。

### 2.1 成熟写作产品的共同模式

| 样本 | 关键做法 | 对笔不怠的启发 |
|---|---|---|
| Scrivener | Binder、Editor、Corkboard/Outliner、Inspector 围绕同一书稿工作；面板可隐藏 | 固定对象，切换视图；不要让每个功能成为独立小应用 |
| Ulysses | Library、Sheet List、Editor 三栏可逐级收起；导出是上下文动作 | 用渐进披露换取专注，不让低频工具常驻 |
| iA Writer | 写作时隐藏资料库与控件；Focus Mode、Typewriter Mode、统计是轻量叠加层 | 冲刺、聚焦、统计应附着写作台，而非成为平级工作台 |
| Dabble | Plot、Write、Edit 围绕同一项目对象；Plot Grid 与书稿层级联动 | 一级导航应按创作阶段组织，而不是按研发阶段组织 |
| Obsidian | 左右侧栏可折叠，工作区布局可保存；窄屏转为单栏 | 保存用户的面板状态和任务预设，减少重复整理 |
| Effie | 极简写作；同一结构可在列表、导图与正文之间转换 | 视觉规划应该是同一故事数据的视图，而不是割裂的资产仓 |
| LivingWriter | Board、Outline、Story Elements 与正文互相引用 | 正典、人物和故事板应使用统一实体与一致的详情交互 |

### 2.2 设计系统的共同原则

- Apple 的 Split View/Sidebar 指南把左侧栏用于顶层层级，把右栏用于详情，并允许面板隐藏与在窄屏下自适应；
- Fluent 2 将颜色、字体、间距、圆角和阴影拆成基础变量与语义变量，用同一语义映射浅色、深色和高对比主题；
- Spectrum 将设计变量视为“设计决策的数据源”，而不是 CSS 中散落的颜色值；
- WCAG 2.2 要求普通文本至少 4.5:1 对比度、键盘焦点清晰可见，并把目标尺寸纳入可访问性质量要求。

### 2.3 GitHub 实现参考与选型

| 项目 | 可参考/采用的能力 | 本项目决策 |
|---|---|---|
| [Radix Primitives](https://github.com/radix-ui/primitives) | 无预设视觉的 Dialog、Popover、Dropdown、Tabs、Tooltip；焦点约束、键盘与碰撞处理 | **选择性采用**。UI-A 先验证 Dialog、Popover、Dropdown 三类复杂交互，样式全部由笔不怠变量控制 |
| [React Aria](https://github.com/adobe/react-spectrum) | 鼠标、触控、键盘、屏幕阅读器和国际化行为 | **备选行为层**。若 Radix 在中文输入、组合框或移动触控上不能满足，再按单组件评估；不采用 React Spectrum 的 Adobe 视觉层 |
| [Lucide](https://github.com/lucide-icons/lucide) | 一致的 SVG 图标与 React 包 | **继续采用**。增加图标语义表，统一 16/18/20/24 四档尺寸，禁止同一动作混用不同图标 |
| [Playwright](https://github.com/microsoft/playwright) | 浏览器旅程、截图比较、Trace 与交互回放 | **UI-E 引入**，用于代表页面和状态的视觉回归；不替代人工视觉评审 |

不建议引入 Ant Design、MUI、React Spectrum 等带强视觉语言的完整组件库；也不直接套用 shadcn/ui 主题。它们会让产品快速“整齐”，但也会稀释现有纸感品牌，并带来第二套变量和密度规则。

UI-A 先用现有 React、CSS 与 Lucide 建立产品自己的视觉层。只有焦点约束、弹层定位、键盘导航等复杂行为才优先交给成熟无样式组件，避免重复实现可访问性基础设施。

## 3. 现状审计

### 3.1 值得保留的基础

- 书架封面、米色画布和纸张编辑区已经形成独有气质；
- 写作台“书稿树—纸张—检查器”的桌面结构正确；
- 文人绿作为操作色比常见科技蓝更贴合中文写作产品；
- 宋体用于作品内容，系统黑体用于控件，层次基本合理；
- 现有工作台均有真实业务闭环，不应为了统一而削减产品能力。

### 3.2 主要问题

#### 问题 A：研发阶段变成了产品导航

当前一级导航只有“写作、剧情、正典、交付”，但视觉故事板、结构模板、安静冲刺、角色审阅、创作来源和加密接力都被堆入“交付”。它们与交付任务并不属于同一心智模型。

结果是“交付”成为杂物抽屉，用户需要记住功能当初在哪个阶段开发，而不是它能解决什么任务。

#### 问题 B：每个阶段追加了一套局部视觉语言

`src/styles.css` 当前审计快照：

| 指标 | 当前值 | 风险 |
|---|---:|---|
| 唯一十六进制颜色 | 248 | 主题、对比度和状态语义难以统一 |
| 圆角声明取值 | 21 | 同层级控件缺少共同形状语义 |
| 字号声明取值 | 17 | 8–10px 微型文字影响可读性 |
| 阴影声明取值 | 29 | 层级表达不稳定，夜间模式维护成本高 |
| 类选择器 | 约 501 | 页面级样式持续复制，变更影响难评估 |
| `!important` | 26 | 样式依赖层级脆弱 |

这些数字不直接等于质量问题，但组合出现说明样式已经从系统演变为“按功能追加”。

#### 问题 C：页面骨架和操作层级不一致

- 书架顶部同时出现七个操作，主次不清；
- 写作台最稳定，但剧情台、正典库和交付台各自拥有不同的页头、侧栏和卡片语法；
- 一些低频基础设施与高频创作动作权重相同；
- 很多 25–29px 图标按钮不适合触屏，8–10px 辅助文字也不适合长期工作；
- 研究台、种子台、波次台等内部能力保留了版本和工程名，不符合作者语言。

### 3.3 根因

当前问题不是“设计得不好看”，而是缺少四个中间层：

1. 没有语义设计变量；
2. 没有稳定的应用壳与页面模板；
3. 没有基础组件与业务组件边界；
4. 没有防止视觉漂移的验收门。

## 4. 统一信息架构

### 4.1 一级工作模式

项目内建议统一为五个主模式：

| 模式 | 用户问题 | 包含能力 |
|---|---|---|
| 写作 | 我现在要把这一场写出来 | 书稿树、正文、场景检查器、AI 候选、专注、冲刺、朗读 |
| 规划 | 接下来发生什么，结构是否成立 | Plot Grid、叙述顺序、故事时间、伏笔、视觉故事板 |
| 正典 | 故事中什么是真的，现在是什么状态 | 人物、地点、组织、物品、事件、知识范围、系列正典 |
| 修订 | 哪里需要判断、修改或交给他人审阅 | 连续性发现、角色审阅、来源证明、版本对比、候选处理 |
| 交付 | 能否安全发布和带走 | 质量检查、渠道规则、预览、导出、完整备份 |

一级导航只表达工作模式，不承担所有入口。

### 4.2 全局工具

以下能力放入应用壳右侧或命令面板，不占一级导航：

- 全局搜索；
- 本地保存/同步状态；
- 接力与设备；
- 通知；
- 设置；
- 帮助与产品研究。

### 4.3 功能迁移表

| 当前入口 | 新位置 | 原因 |
|---|---|---|
| 安静冲刺 | 写作台工具栏/专注模式 | 它是写作状态，不是交付工作台 |
| 视觉故事板 | 规划 | 是场景的另一种视图 |
| 结构模板 | 书架“新故事”流程与模板库 | 服务于创建结构，不服务于发布 |
| 角色审阅 | 修订 | 属于外部反馈与逐条处理 |
| 创作来源 | 修订 | 用于核对来源和版本责任 |
| 加密接力 | 全局设备/接力入口 | 是跨工作流基础设施 |
| 朗读 | 写作工具栏；交付预览可再次调用 | 写作校对与发布预览均可使用同一能力 |
| 真实验证/种子研究 | 设置 → 帮助改进笔不怠 | 只对参与者和协调员渐进披露 |

### 4.4 书架动作降噪

书架顶部只保留：

- 主操作：`新故事`；
- 次操作：`导入旧稿`；
- 全局入口：搜索、接力/同步状态、更多。

回收站、恢复备份、审阅任务、产品研究等进入“更多”菜单或按状态出现。最近项目卡本身就是“继续写”的主入口，不再额外增加按钮。

## 5. 应用壳与布局

### 5.1 稳定壳层

所有项目工作台共用：

```text
┌ 项目标题 ─ 写作 规划 正典 修订 交付 ───── 搜索 保存状态 更多 ┐
├ 左侧层级/列表 ┬──────── 主内容 ────────┬ 右侧详情/检查器 ┤
│ 可折叠         │ 正文、看板、表单、预览   │ 可折叠            │
└────────────────┴─────────────────────────┴───────────────────┘
```

规则：

- 左栏始终表示“对象导航”，右栏始终表示“当前对象的详情、检查或候选”；
- 右栏不作为新的主导航；
- 每个模式记住自己的侧栏宽度、展开状态和上次对象；
- `⌘K / Ctrl+K` 打开命令面板，用于跨模式搜索功能和对象；
- 专注模式只保留正文、返回按钮、保存状态和非打扰统计。

### 5.2 响应式分档

| 宽度 | 布局 |
|---|---|
| ≥ 1280 | 左栏 264–320px + 主内容 + 右栏 300–360px，可分别折叠 |
| 1024–1279 | 左栏 + 主内容；右栏改为抽屉 |
| 760–1023 | 单主内容；左栏和右栏都由抽屉进入 |
| < 760 | 单任务移动布局；每次只展示一个主要层级，底部安全区适配 |

不允许仅通过缩小字体把桌面三栏塞入窄屏。

### 5.3 四种页面模板

| 模板 | 适用页面 | 固定结构 |
|---|---|---|
| Editor | 写作 | 层级树 + 内容画布 + 检查器 |
| Board | 剧情、故事板、伏笔 | 页头 + 视图切换/筛选 + 看板画布 + 可选详情 |
| Library | 正典、系列、模板 | 分类列表 + 对象列表 + 对象详情 |
| Workflow | 修订、交付、研究任务 | 摘要/进度 + 步骤或发现列表 + 当前结果/操作 |

任何新增工作台必须先选择一种模板；确实无法适配时才新增模板，并记录设计决策。

## 6. 视觉语言

### 6.1 三层表面

| 层 | 含义 | 默认表达 |
|---|---|---|
| Canvas | 应用背景、导航与工具环境 | 暖米灰，低对比 |
| Paper | 正文、预览、主要阅读内容 | 接近白纸，最高阅读对比 |
| Tool | 卡片、面板、弹层和交互控件 | 中性浅面，边框优先于阴影 |

正文纸张和工具面板不能使用完全相同的白色，否则阅读区会失去中心地位。

### 6.2 色彩原则

- 文人绿：主操作、选中态、焦点和可靠状态；
- 朱砂：品牌点睛、章节标记和少量强调，不作为所有眉题的默认颜色；
- 黄/红/蓝：只表达警告、错误和信息，不用于装饰；
- 状态不能只靠颜色，必须同时有图标或文字；
- 功能 CSS 禁止写裸颜色值，全部通过语义变量引用。

建议变量结构：

```css
/* primitive */
--green-700; --rice-50; --rice-100; --ink-900; --cinnabar-600;

/* semantic */
--surface-canvas; --surface-paper; --surface-raised;
--text-primary; --text-secondary; --text-tertiary;
--border-subtle; --border-strong;
--action-primary; --action-primary-hover; --action-danger;
--status-success; --status-warning; --status-danger; --status-info;
--focus-ring;
```

目标：色板原始值不超过 24 个，功能样式中的裸颜色值为 0。

### 6.3 字体阶梯

| 角色 | 字体 | 建议规格 | 用途 |
|---|---|---|---|
| Display | 宋体/衬线 | 32/40 | 空状态、书架品牌标题 |
| Page title | 宋体/衬线 | 24/32 | 工作台标题 |
| Section title | 宋体/衬线或黑体 | 18/26 | 内容分区标题 |
| Body | 系统黑体 | 14/22 | 控件说明、表单与常规正文 |
| Label | 系统黑体，中等字重 | 13/18 | 标签、按钮、字段名 |
| Caption | 系统黑体 | 12/16 | 非关键辅助信息的最小字号 |
| Manuscript | 可配置宋体/黑体 | 默认 18/36 | 作品正文，允许字号、行高、栏宽独立调整 |

禁止关键文本低于 12px；不使用全大写英文制造层级；中文按钮优先使用 2–6 字动作短语。

### 6.4 间距、圆角、阴影和动效

- 间距：`4 / 8 / 12 / 16 / 24 / 32 / 48`；
- 圆角：`6`（小控件）、`10`（常规卡片）、`14`（大容器）、`999`（胶囊）；
- 阴影：仅 `none / raised / floating / modal` 四档；常规分组优先用留白和边框；
- 动效：`120ms / 180ms / 240ms` 三档；只解释状态或空间变化；
- 尊重 `prefers-reduced-motion`，关闭非必要位移和缩放。

### 6.5 密度

提供三档但只维护一套组件：

- 舒适：默认，表单与列表行 40px；
- 紧凑：大量正典和检查结果，列表行 32px；
- 触控：移动/PWA，交互目标至少 44px。

密度由容器上下文决定，不允许每个页面自行缩小字号。

### 6.6 品牌与口号

品牌口号固定为：

> **笔耕不怠，写尽所思。**

口号用于书架欢迎区、首次启动、关于页和正式宣传物；进入项目后的高频工作台不重复展示，避免品牌信息干扰正文。品牌字“笔”、产品名、口号和版本号分别使用固定组件，不在各页面自行组合字号与颜色。

## 7. 组件体系

### 7.1 基础组件 P0

1. `Button`：primary / secondary / ghost / danger，small / medium / large；
2. `IconButton`：统一尺寸、提示、按下态和可访问名称；
3. `Field`：Label、Input、Textarea、Select、Checkbox、Switch、错误与帮助文案；
4. `Tabs` 与 `SegmentedControl`：明确“切页面”和“切视图”的区别；
5. `PageHeader`：眉题、标题、说明、主/次操作；
6. `Pane`、`PaneHeader`、`PaneBody`：左右栏共同语法；
7. `Card`：plain / selectable / metric / status 四种语义；
8. `ListRow`、`TreeRow`、`EntityRow`：列表结构、选中和拖动一致；
9. `Badge`、`InlineNotice`、`Toast`：状态反馈统一；
10. `Modal`、`Drawer`、`Popover`、`DropdownMenu`：浮层层级与关闭行为统一；
11. `EmptyState`、`Skeleton`、`ErrorState`：空、加载、失败状态统一；
12. `Toolbar`、`ToolGroup`：编辑器和看板的工具分组统一。

### 7.2 必须覆盖的状态

每个交互组件都必须定义：

- default；
- hover；
- active/pressed；
- selected；
- keyboard focus；
- disabled；
- loading；
- error；
- night/high contrast。

业务页面只能组合组件，不自行创造按钮、输入框、徽标或浮层视觉。

### 7.3 业务复合组件 P1

- `ManuscriptTree`；
- `SceneHeader`；
- `ContextCapsule`；
- `FindingList`；
- `CandidateDiff`；
- `CanonEntitySummary`；
- `SaveSyncStatus`；
- `ExportJobCard`；

- `EvidenceQuote`。

复合组件可以有业务逻辑，但底层必须使用 P0 基础组件和语义变量。

## 8. 关键页面改造

### 8.1 书架

- 保留封面式项目卡与品牌标题；
- 顶部从七个并列按钮收敛为“新故事、导入旧稿、更多”；
- 项目卡主点击直接继续上次位置；
- 状态信息固定为：最近编辑、进度、保存/接力异常；
- 模板库从“交付”迁入新建流程；
- 回收站与备份恢复使用 Workflow 模板。

### 8.2 写作台

- 维持现有三栏优势；
- 主导航和工具栏分层，避免所有图标同权重；
- 冲刺、朗读、专注、统计作为写作模式/轻量面板；
- 右栏固定为“场景、正典、检查、候选”四类页签；
- 关闭右栏后，正文纸张自动居中并保持用户设置的最大栏宽；
- AI 上下文通过一个可检查的 Context Capsule 进入，不常驻大聊天框。

### 8.3 规划

- Plot Grid、叙述顺序、故事时间、伏笔、故事板成为同一模式下的视图；
- 共用筛选器、场景卡、选中态和详情栏；
- “列表/时间轴/看板/故事板”只是同一数据的表现方式；
- 空项目使用引导式空状态，不展示大面积无意义画布。

### 8.4 正典

- 左栏只放实体分类与筛选，中栏放对象列表，右侧/主区放详情；
- 所有实体详情共用标题、状态、证据、时态记录和关联对象结构；
- 系列覆盖、视角知识和视觉锚点作为对象详情中的能力，不再形成不一致的独立壳。

### 8.5 修订

- 将连续性检查、候选事实、角色审阅、来源证明统一为“发现 → 证据 → 决定 → 记录”；
- 列表左侧表示严重度和类型，中部显示证据，右侧提供接受/修改/忽略；
- 技术审计信息默认折叠，作者首先看到影响和下一步动作。

### 8.6 交付

- 首屏回答“是否可以发布”，用汇总状态而非六个工具入口；
- 流程统一为：选择目标 → 运行检查 → 处理阻塞 → 预览 → 导出/备份；
- 渠道规则、朗读预览、导出任务和备份任务共用 Workflow 模板；
- 所有规则显示更新时间、证据和开关，避免假装平台规则永久有效。

## 9. 内容与交互规范

- 一个区域最多一个主按钮；其他动作降为次按钮、菜单项或行内动作；
- 动作使用动宾短语：`新建场景`、`接受候选`、`导出书稿`；
- 不在作者界面显示 V1-A、R1-C、G4-B 等研发阶段名；
- 错误文案包含“发生了什么、是否影响稿件、可以怎么做”；
- 保存状态必须是明确文字：已保存到本机、等待同步、离线、需要处理；
- 危险动作说明影响范围，并提供可恢复路径；
- 空状态只提供一个明确下一步，不堆功能介绍；
- 键盘操作、鼠标操作和触屏操作共享同一任务结果。

## 10. 实施路线

建议把下一版本命名为 **UI-1 / 1.7.0：统一工作台**。分五个可独立验收的阶段推进。

### UI-A：设计基础

交付：

- 设计变量文件与浅色/夜间/高对比映射；
- 字体、间距、圆角、阴影、动效规范；
- P0 基础组件；
- 开发态 Design Gallery，展示所有组件和状态；
- 禁止新增裸颜色和一次性按钮样式的静态检查。

验收后才能改大页面，防止一边迁移一边继续漂移。

### UI-B：壳层与信息架构

交付：

- 五模式导航；
- 全局工具区与命令面板；
- 书架动作降噪；
- 左/右栏折叠、宽度和模式状态持久化；
- 安静冲刺、故事板、模板、审阅、来源和接力按新架构迁位。

### UI-C：核心工作台模板化

交付：

- 写作台迁移到 Editor 模板；
- 规划迁移到 Board 模板；
- 正典迁移到 Library 模板；
- 共用页头、工具栏、空状态、列表行、卡片和详情栏；
- 保持现有数据与操作行为不变。

### UI-D：长尾工作流统一

交付：

- 修订与交付迁移到 Workflow 模板；
- 研究、恢复、审阅接力、同步冲突等低频流程统一；
- 全量夜间模式、触控密度和窄屏布局；
- 文案去工程化。

### UI-E：质量门与收尾

交付：

- 视觉回归基线；
- 键盘、屏幕阅读器、对比度和缩放检查；
- macOS/Windows/PWA 代表尺寸验收；
- 20 万字项目的布局和滚动性能检查；
- UI 规范、组件用法和新增页面准入规则归档。

### 推荐实施顺序

```text
UI-A 变量与组件
  → UI-B 应用壳与导航
    → UI-C 写作/规划/正典
      → UI-D 修订/交付/长尾流程
        → UI-E 可访问性与视觉回归
```

不要按页面逐个“美化”。如果没有先完成 UI-A 和 UI-B，后续仍会生成新的局部系统。

## 11. 验收门

### 11.1 系统一致性

- 功能 CSS 裸颜色值为 0；所有颜色来自语义变量；
- 原始色板值不超过 24，圆角 4 档，阴影 4 档，间距使用统一阶梯；
- 100% 项目内页面使用 AppShell；
- 100% 页面根结构属于四种模板之一；
- 100% 按钮、字段、页签、弹层、通知使用基础组件；
- 新增页面不允许复制整段页面级按钮和表单样式。

### 11.2 可读性与可访问性

- 关键文本不低于 12px，常规 UI 正文不低于 14px；
- 普通文本对比度至少 4.5:1，大文本和非文本界面至少 3:1；
- 所有操作可用键盘完成，焦点不被遮挡且清晰可见；
- 触控密度的目标尺寸至少 44×44px；桌面紧凑模式也不得低于 WCAG 2.2 AA 的最低目标要求；
- 状态不只依赖颜色；图标按钮均有可访问名称和提示；
- 200% 缩放可完成核心流程，无关键内容截断；
- 支持减少动态效果。

### 11.3 响应式矩阵

至少在以下视口逐页检查浅色与夜间模式：

- 1440×900；
- 1280×800；
- 1024×768；
- 430×932；
- 390×844；
- 360×800。

核心页面不得出现非设计意图的横向滚动；抽屉打开后焦点被约束，关闭后回到触发控件。

### 11.4 任务指标

- 从书架新建故事：1 个主操作可达；
- 继续最近书稿：点击项目卡一次可达；
- 进入/退出专注：1 个动作；
- 任一一级工作模式：1 次导航可达；
- 完成导出：选择目标后不超过 3 个关键决策步骤；
- 恢复备份：不超过 2 个关键决策步骤，恢复前明确预览影响；
- 保存/同步异常在所有模式中使用同一位置和同一语言。

### 11.5 视觉回归代表状态

至少保存以下基线：

- 空书架、正常书架、书架恢复入口；
- 写作三栏、仅正文、右栏候选、保存异常；
- 剧情空状态和有数据看板；
- 正典列表和时态详情；
- 修订发现列表与 Diff；
- 交付可发布、阻塞、导出中、导出完成；
- 模态框、抽屉、下拉菜单、Toast；
- 浅色、夜间、高对比和移动触控密度。

### 11.6 回归与性能

- 现有单元/集成测试保持通过；
- 关键用户旅程增加浏览器级测试；
- 浏览器控制台无未处理错误，核心请求无意外 4xx/5xx；
- 20 万字书稿的切章、输入、滚动、打开检查器不因视觉重构产生明显退化；
- 中文输入法组合输入过程中不得触发错误快捷键或丢字。

## 12. 决策边界

本阶段不做：

- 更换编辑器技术栈；
- 重写已有业务服务和数据协议；
- 为追求视觉效果加入大量插画和重动效；
- 引入新的社交或 AI 功能；
- 用一次性页面样式绕过组件系统；
- 把内部研究协调台提升为普通作者的主导航。
