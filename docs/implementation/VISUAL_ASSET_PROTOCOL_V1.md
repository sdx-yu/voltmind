# `bbd-visual-v1` 本地视觉资产与正典绑定协议

状态：V2-V 1.3.0 冻结。

## 目的

协议用于把作者本地导入的图片作为候选资产绑定到明确的文字正典快照，并为场景建立不含正文的故事板。图片永远不是文字事实的上游来源；系统不会依据图片修改人物、地点、物品、状态或剧情。

## 正典快照

视觉锚点必须关联当前项目内未删除的人物、地点或物品。作者逐项选择可进入视觉描述的字段：

- `canonicalName`：必选；
- `summary`、`aliases`：可选；
- `state:<id>`：可选，且状态必须属于同一正典项。

`local_private` 正典整体不可读取。未选择字段不会进入快照、视觉描述、候选或故事板。`canonHash` 对正典类型、已选字段名和对应值的规范化 JSON 计算 SHA-256；不把数据库 ID、更新时间或未选字段纳入哈希。这样普通备份恢复后的等价正典仍得到相同版本哈希。

## 视觉资产

- 1.3.0 只接受真实 PNG 或 JPEG，最大 10 MiB；
- 服务端按魔数读取真实类型与尺寸，不信任文件扩展名、浏览器 MIME 或客户端尺寸；
- 宽高均需在 1–20,000，像素总数不超过 100,000,000；
- `contentHash = SHA-256(original bytes)`，相同内容全库复用；同哈希异内容按碰撞阻断；
- 原始字节存入 SQLite BLOB，读取响应固定真实 MIME、`nosniff` 和私有不可变缓存；不接受 SVG、HTML 或可执行载荷。

## 候选与接受

导入只创建 `pending` 候选，冻结导入时的视觉描述与 `canonHash`。作者可以接受或拒绝：

- 接受前再次计算当前所选正典字段哈希；若已变化则阻断，要求先刷新锚点；
- 接受只更新锚点的候选/资产引用，不调用正典更新 API；
- 新候选被接受时，旧定稿标记为 `superseded`，历史与资产仍可审计；
- 拒绝不删除资产或审计事件；
- 正典选中字段后来变化时，绑定显示 `stale`；刷新描述不会把旧图自动升级为当前定稿。

## 故事板

故事板按场景建立，卡片按 `position` 排序。卡片只能包含：

- 镜头目的、作者备注和本地视觉描述；
- 当前项目内的视觉锚点 ID；
- 所选锚点已接受的资产哈希；
- 每个锚点在建卡时的 `canonHash`。

故事板不读取或复制场景正文。卡片重排和删除不修改场景、正典、视觉锚点或资产。

## 本地 Provider 边界

1.3.0 不连接远程图像 Provider，也不声称已经生成图片。作者可以复制本地视觉描述，自行交给明确选择的外部工具，然后把结果作为候选导入。未来 Provider 必须单独冻结供应商、发送字段、凭据存储、费用、版权、审核、数据保留、失败重试与撤回政策；没有完成这些门禁前不得复用文本 AI 设置静默发送正典。

## 备份与来源

普通 `bbd-backup-v2` 保存项目使用的原始资产字节、锚点快照、候选决定、故事板、卡片和视觉事件；恢复时验证图片哈希、MIME、尺寸、正典哈希并重映射实体/场景/锚点引用。视觉创建、刷新、导入、接受、拒绝和故事板变化同时进入创作来源链，但来源元数据不含场景正文。

## 威胁与限制

- SHA-256 证明内容完整性，不证明图片版权、作者身份或来源真实性；
- 文件名和“作者本地导入”是本地标签，不是签名；
- 不做图片隐写、恶意内容、版权相似性或真人身份识别；
- SQLite 资产会增加普通备份体积，作者应继续保留快照和离线副本；
- 远程生成质量、角色跨图一致性和供应商条款不是本机工程结论。
