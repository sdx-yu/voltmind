# `bbd-sync-v1` 协议、威胁模型与云端契约

状态：0.8.0 冻结。本文描述工程验证协议，不代表云服务已经上线。

## 1. 信任与威胁边界

本机应用和作者掌握恢复短语；传输文件、未来中继服务、对象存储和网络均按“不可信但可用”处理。协议防护以下风险：

- 中转方读取项目标题、正文、正典、来源摘录或附件；
- 信封头、认证标签、密文或单个分块被修改；
- 重复、乱序、缺块、重试或进程在事务中断；
- 两台离线设备同时编辑正文或业务对象；
- 错误恢复短语、丢失设备与全新设备恢复。

协议不防护已解锁本机上的恶意软件、作者主动泄露恢复短语、屏幕录制、弱操作系统账户，也不提供服务器身份、账户找回、设备吊销或法律意义的可信时间戳。

## 2. 密钥生命周期

1. 初始化生成 24 个随机字节，以 12 组十六进制短语显示一次；熵为 192 bit，不依赖用户自选口令。
2. 每项目随机生成 16 字节盐；scrypt 参数为 N=32768、r=8、p=1，输出 32 字节密钥。
3. 数据库只保存盐和 `HMAC-SHA-256(key, "bbd-sync-v1-key-verifier")`。恢复短语和派生密钥不落库、不进入普通备份、不写日志。
4. 错误短语在解密前由定时安全比较阻断；AES-GCM 认证标签仍作为最终完整性门。
5. 新设备用接力包、恢复短语和新的设备名称建立新 device ID。设备 ID 不从旧设备克隆。

0.8.0 不实现服务器辅助找回。短语和所有已解锁设备同时丢失时，密文不可恢复，这是端到端加密的预期后果。

## 3. 信封与载荷

明文信封只包含协议版本、包 ID、项目指纹、发送设备 ID/名称、包序号、版本向量、盐、密钥验证值、nonce、认证标签、哈希、分块尺寸/数量和创建时间。项目指纹为项目 ID 与盐的单向摘要，不暴露书名。

完整载荷经 AES-256-GCM 加密，包括：

- 项目元数据与书—卷—章—场景树；
- 场景正文、不可变版本、Yjs 完整状态和对象版本向量；
- 正典实体、时态状态、删除墓碑和对象版本向量；
- 来源事件链；
- 导入原件等附件及 `sha256:<digest>` 内容地址。

密文按 65,536 字节切块。每块携带索引与 SHA-256，整段密文另有 SHA-256；信封头序列化后作为 AES-GCM AAD 并单独哈希。接收端必须先验证格式、短语、块序号/块哈希、整段哈希、AAD 和认证标签，再校验解密载荷与附件内容地址，最后开启数据库事务。

## 4. 顺序、幂等与恢复

- 项目向量为 `{deviceId: sequence}`。导出只推进本设备分量；导入取逐分量最大值。
- 密文哈希是本地幂等键。同一包无论来自“已导出”还是“已导入”记录，都直接返回 duplicate，不重复写版本或冲突。
- 乱序旧包若被本地向量支配，不覆盖新状态；并发包进入 CRDT 合并或业务冲突。
- 缺块包不进入事务。未来中继可按缺失索引重取；手动文件模式要求重新传递完整包。
- 所有对象、来源事件、队列和冲突在一个 `BEGIN IMMEDIATE` 事务中落库；进程中断只可能是整包提交或整包回滚。

## 5. 分层合并语义

| 对象 | 非并发 | 并发 |
|---|---|---|
| 场景正文 | 应用远端 Yjs 状态 | 合并 Yjs 更新，生成 `merge` 版本和 `sync_merge` 来源事件 |
| 场景删除/编辑 | 应用支配方 | 建立 `delete_edit`，作者选择本机或接力包 |
| 正典与状态 | 应用支配方 | 建立 `structured_concurrent_edit`；不做字段级猜测 |
| 正典删除/编辑 | 应用支配方 | 建立 `delete_edit` |
| 来源事件链 | 严格前缀可追加 | 建立 `provenance_fork`；只能保留本机链或知悉远端分叉，禁止静默重写 |
| 附件 | 以内容哈希去重 | 同哈希视为同一不可变内容 |

Yjs 历史只表达文本操作的合并关系，不替代剧情故事时间、正典有效期或创作来源证明。

## 6. 未来中继服务最小接口

云端只需实现不理解密文内容的包邮箱：

- `POST /v1/projects/{fingerprint}/packages`：上传信封和分块；以 `packageId + ciphertextHash` 幂等；
- `GET /v1/projects/{fingerprint}/packages?after=<vector>`：列出设备、序号、向量、块清单和创建时间；
- `GET /v1/projects/{fingerprint}/packages/{packageId}/chunks/{index}`：按块续传；支持 Range/ETag；
- `POST /v1/projects/{fingerprint}/acks`：设备确认已持久化的包与向量；
- `DELETE /v1/projects/{fingerprint}`：账号所有者请求删除全部密文、索引和备份副本。

服务端不得接收恢复短语、派生密钥、解密后的标题/正文/正典/来源或附件。日志不得记录完整包、验证值、认证标签或可长期关联的客户端 IP；错误返回只使用包 ID 和块索引。

## 7. 保留、删除与运营要求

- 未确认包的默认保留期、已确认包压缩策略和配额必须在上线前公开；建议在所有活跃设备确认且经过安全窗口后回收旧密文。
- 项目删除要覆盖主存储、分块、索引、缓存、日志中的可识别引用和备份轮换，并给出删除 SLA。
- 设备丢失后的吊销、密钥轮换、成员变更、账号恢复和滥用防护尚未定义，不能据此协议直接开放多人协作。
- 上线前必须完成两台真实设备、断网/睡眠/升级、限速/丢包、容量、跨地区、渗透测试和隐私法律评审。

## 8. 本机证据

`SyncService.runDrill()` 提供五项无书稿内存演练：密文可见性、错误短语、Yjs 乱序/重复收敛、缺块检测与并发向量。自动化另以两个隔离 SQLite 数据库验证新设备恢复、并发正文收敛、正典冲突、删除/编辑、来源分叉、重复包和附件内容寻址。
