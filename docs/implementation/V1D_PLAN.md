# V1-D 本地朗读与平台交付模板（0.6.0）

状态：已完成并通过工程验收（2026-08-26）。桌面端通过 Tauri WebView 的系统语音接口调用本机声音，Web 端使用同一 Web Speech 状态机降级。

## 目标

把“写完后的耳朵校对”和“投递前的平台整理”变成可关闭、可追溯、不会伪装成平台官方保证的本地工作流。

## 产品语义

- 朗读默认使用操作系统本地语音能力，不把正文上传到第三方；
- 作者可朗读当前选区、当前场景或指定章节范围，并控制播放、暂停、停止、语速和系统声音；
- 朗读位置必须在正文中可见，切换场景或关闭朗读时不得继续后台播放；
- 交付模板保存渠道、规则版本、核验日期、来源说明、启用状态和作者自定义覆盖；
- 内置规则只能称为“核验辅助”，不得宣称保证通过平台审核；过期规则必须醒目标记；
- 所有规则可逐项关闭，检查结果必须引用规则编号与命中文本；
- 朗读设置、模板、关闭状态与项目覆盖进入离线备份，旧备份继续可恢复。

## 实施步骤

1. migration v6：朗读偏好、渠道模板、模板规则、项目覆盖与检查记录；
2. Tauri 本地朗读桥接与 Web 降级能力，建立统一播放状态机；
3. 编辑器增加选区/场景/章节朗读入口和可见进度控制；
4. 交付台增加版本化渠道模板、过期提示、逐项开关和命中证据；
5. 导出继续复用现有 TXT/Markdown/DOCX 范围能力，模板只改变明确选择的格式参数；
6. 备份恢复、失败降级、自动化、真实浏览器、桌面实机和归档。

## 验收主流程

选择当前场景 → 本地朗读 → 暂停/恢复/调速 → 定位到正在朗读的段落 → 停止后无后台音频 → 选择渠道模板 → 显示规则版本与核验日期 → 关闭一条规则后不再报告 → 命中项可定位原文 → 导出所选章节 → 备份恢复后偏好、模板覆盖和开关一致。

## 明确不做

- 云端语音合成、声音克隆或上传正文换取朗读；
- 绕过平台审核、自动投稿或代替作者接受平台协议；
- 把未经核验的网络帖子包装成官方规则；
- 在规则过期后静默继续给出“合规”结论。

## 外部门

- 各平台真实规则需要在实现时重新访问官方来源并记录核验日期；
- 正式对外分发仍需要 Developer ID 签名与 Apple 公证；
- 平台端实际投稿结果只能由真实账号和真实投稿验证，不能用本地模拟替代。
