# V1-S 加密同步工程验证（0.8.0）

状态：规格冻结。真实云端、账号与双设备验证属于外部门，不把单机模拟写成上线通过。

## 目标

验证“本地仍是主副本”的多端同步基础：正文、结构化正典和来源链能够加密传输、可恢复密钥、可解释冲突，并在服务不可用时继续写作。

## 可独立完成的工程范围

1. 固定同步对象、版本向量、删除墓碑、附件寻址和来源事件的协议版本；
2. 对 Tiptap/Yjs 与结构化业务对象做分层 spike，不把 CRDT 历史误当剧情时间或来源证明；
3. 实现客户端端到端加密封装、密钥派生、恢复短语与错误密钥阻断；
4. 用两个隔离本地副本模拟离线编辑、乱序、重复、重试、冲突与断点续传；
5. 为正文自动合并、正典字段冲突、删除/编辑冲突建立作者可理解的处理规则；
6. 给来源链定义跨设备合并规则，任何哈希断裂必须进入显式冲突，不静默重写；
7. 形成云端最小接口契约、威胁模型、数据保留和账号删除需求，不在无授权条件下部署服务。

## 验收门

- 两个隔离副本在离线并发编辑后能够确定性收敛；
- 重复、乱序、丢包和进程中断不丢已确认版本；
- 服务端看不到正文、正典、来源摘录或恢复短语明文；
- 丢失设备、错误密钥和恢复短语三条流程有自动化证据；
- 来源事件链合并后可验证，冲突不会被伪装成普通人工版本；
- 原有单机写作、备份恢复和 0.7.0 来源导出继续通过。

## 外部门

- 真实云服务部署、域名、账户、邮件和运维授权；
- 至少两台真实设备的断网/联网、睡眠唤醒和系统升级矩阵；
- 隐私政策、数据处理协议、删除 SLA 与安全审计；
- 正式计费、容量和跨地区合规。
