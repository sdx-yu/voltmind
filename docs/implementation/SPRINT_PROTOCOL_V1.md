# `bbd-sprint-v1` 成果卡协议与威胁模型

状态：V2-F 1.1.0 冻结。

## 目标

让作者手动交换“不含正文的冲刺结果”，并在离线小组看板中做可重复、可校验的目标汇总。协议证明一张卡在导出后是否被意外修改，不证明作者的真实身份、在线状态或写作过程没有作弊。

## 顶层格式

```json
{
  "format": "bbd-sprint-v1",
  "protocolVersion": 1,
  "card": {},
  "events": [],
  "cardHash": "sha256"
}
```

`card` 只允许：随机卡 ID、自填参与者标签、场景/项目范围类别、项目与范围脱敏指纹、开始/结束时间、有效时长、目标字数、净新增、事件链头、事件数和创建时间。

默认禁止并由严格 Schema 排除：书名、场景名、正文、正典、Prompt、AI 输出、设备 ID、项目/场景本地 ID、恢复短语和 API Key。

## 计量语义

- 开始时冻结范围内每个场景的当前版本 ID、内容哈希和字数；
- 结束时再次从已保存版本取样；
- `netWords = endTotalWords - startTotalWords`，因此粘贴只增加一次，撤销和删除会抵消，按键次数不参与；
- 场景冲刺只计指定场景；项目冲刺计开始时范围内的项目场景；
- 编辑器仍按正常自动保存策略工作，结束动作不会另行自动提交未确认内容；写作 HUD 会先请求编辑器刷新待保存内容。

## 可信计时与异常

- 倒计时来自 `startedAt - totalPausedMs` 的墙钟对账，不依赖单个递减 interval；
- 暂停与恢复均追加不可变事件；
- 页面离开或睡眠超过阈值时，以最后可见时间保守暂停，未知时段不计入有效时长；
- 服务端时钟回拨超过容差时暂停并记录 `clock_anomaly`；
- 睡眠或时钟异常后必须由作者显式恢复；到时只提醒，不自动结束、不自动提交正文。

## 事件链

事件顺序为 `started`、可选的 `paused/resumed/sleep_detected/clock_anomaly`，以及 `completed` 或 `cancelled`。每项包含随机 ID、类型、时间、累计有效时长、受限元数据、前序哈希和事件哈希。

```text
eventHash = SHA-256(JSON({ type, occurredAt, activeElapsedMs, metadata, previousHash }))
cardHash  = SHA-256(JSON({ card, events }))
```

导入时必须验证严格 Schema、完整事件链、链头、事件数、时间边界和整卡哈希，任一步失败都不得落库。

## 幂等与碰撞

- 看板键为 `(boardId, cardId)`；
- 同 ID、同 `cardHash` 重复或乱序导入返回幂等成功，不重复累计；
- 同 ID、不同 `cardHash` 视为碰撞并阻断；
- 卡片结束时间必须落在看板固定的日/周周期内。

## 明确不保证

- SHA-256 不是作者签名，持包者可以重建一张新的自洽卡；
- 参与者名称是自填标签，不是认证身份；
- 脱敏指纹仅用于同源提示，不是公开项目身份；
- 协议不提供防作弊、在线 presence、排行榜公证、服务器时间戳或跨网络撤回。
