# 场景进度功能真值规格

状态：2.8.1 已实施。

## 产品定义

场景进度不是六个可以任意切换的标签，而是两类信息：

- 写作过程：想法、计划、草稿、修订中；作者可直接切换。
- 结果状态：已完成、已发布；必须由对应业务动作产生，不能通过普通选择框伪造。

当前版本已经存在“完成本场景并提取事实”的完整动作，因此“已完成”由该动作写入。项目尚未实现真实发布渠道、交付确认和发布凭据，所以“已发布”只作为旧数据兼容状态展示，不提供新增入口。

## 状态规则

1. 普通进度选择器只包含想法、计划、草稿和修订中。
2. 完成动作先提取事实候选、运行连续性检查，再写入已完成状态。
3. 已完成或历史已发布场景不重复显示完成按钮；用户可以显式进入修订。
4. 已完成或已发布场景的正文发生真实内容变化时，自动切换为修订中。
5. 内容哈希没有变化的重复保存不改变状态。
6. 备份导入和加密同步用于还原既有真值，不因技术性写入把终态改成修订中。
7. 恢复历史版本、接受 AI 改写和其他会改变当前正文的操作属于内容修改，统一进入修订中。

## UI 规则

- 普通状态使用标准选择器；终态使用只读状态卡和“进入修订”次级动作。
- 故事时间是独立工作流入口，不与进度选择器在视觉上粘连。
- 视角人物继续使用标准选择器，三个字段按统一垂直节奏排列。
- 多列表单中的字段容器统一顶对齐；帮助文案只占所属字段的下方空间，不能把相邻输入框推离同一基线。

## 数据兼容

数据库枚举继续保留 `complete` 与 `published`，避免旧备份或同步包丢失信息。通用节点更新接口只接受四个过程状态；完成状态只能经完成接口写入。未来实现真实发布工作流时，应新增独立发布动作、发布记录和撤回规则，而不是把“已发布”放回普通进度选择器。

## 验收条件

- 服务端拒绝通过通用更新接口直接设置已完成／已发布；
- 完成动作成功后返回已完成，重复完成返回冲突提示；
- 终态场景内容改变后返回修订中，未改变内容则保持终态；
- 同步和备份恢复保持原终态；
- UI 即时消费保存接口返回的新节点状态；
- 真实浏览器可完成“完成场景 → 修改正文 → 自动回到修订中”的闭环；
- UI 静态门、类型检查、单元／集成测试、生产构建与端到端测试全部通过。
