# R1-B 受控种子验证执行台（1.5.0）

状态：R1-B 执行台本机工程通过（1.5.0）。真实作者数量、真实周期、人工结论和 R1 发布决定仍为外部门，当前真实样本计数为 0。

## 目标

让研究负责人在本机接收并核验多个 `bbd-research-v1` 包，区分真实外部证据与工程夹具，验证同一参与者的事件链连续性，按固定规则计算两周/四周门，并执行到期清除和退出删除。工具只能显示“试点阈值是否满足”，不能自动把 R1 或公开发布改为 GO。

## 范围

1. migration v15：参与者哈希、人工资格声明、提交摘要和删除回执；
2. `r1b-cohort-v1`：参与码只保留 SHA-256，同意回执和证据类型不可静默更换；
3. 导入前严格校验研究包 Schema、manifest、事件链、任务—事件—进度语义一致性；
4. 同一参与者的新包必须是旧事件链的严格前缀扩展；相同链头幂等，不接受回退或分叉；
5. `external_attested` 必须由负责人逐项确认目标作者、独立参与、稿件授权和真实使用；`engineering_fixture` 永不计入门禁；
6. 固定分层为日更网文、完稿/修订、AI 辅助和其他目标长篇作者，不提供自由文本；
7. 两周资格为 ≥2 个自然周桶且同意至最近完成任务跨度 ≥8 天；四周资格为 ≥4 个自然周桶且跨度 ≥22 天；
8. 到期清除和退出删除移除参与者与全部提交摘要，只保留不可逆双哈希删除回执；
9. 导出 `bbd-cohort-v1` 聚合报告，不包含参与码、书名、正文、项目/任务 ID、Prompt、密钥、路径或原始研究包。

## 试点门

- 至少 5 名人工核对的真实作者满足两周资格；
- 至少 3 名满足四周资格；
- 至少 3 名跨两周完成过 ≥2 次正典核心闭环；
- 不可恢复数据丢失报告为 0；
- 所有达到的数值仍需研究负责人复核原始离线包和招募记录。

试点门小于最初 G5 的 20 人/12 人四周商业成功门，只用于确认研究执行可继续，不能替代完整商业验证。

## 不计数边界

- 自动化、浏览器、开发者 dogfood 和演示包；
- 没有四项负责人声明的导入；
- 事件链分叉、回退、同意回执变化或语义不一致的包；
- 已过保留期限、已执行删除请求或仅导出但没有完成任务的参与者；
- 截图、口头数字、人工编辑 JSON 或无法提供原始包的汇总。

## 本机工程退出条件

- 导入、预检、人工声明、幂等、连续更新、分叉阻断、聚合、导出、到期清除和退出删除均有自动化证据；
- 真实界面可完成工程夹具导入，页面持续明确夹具不计数且 R1 为 NO-GO；
- 全量回归、真实浏览器和 1.5.0 桌面构建通过；
- 验收报告只声明“R1-B 执行台工程通过”，真实种子验证仍等待外部执行。
