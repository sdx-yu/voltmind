# 备份与恢复指南

## 日常备份

1. 在“交付”页下载“完整离线备份”；该文件可在书架的“恢复备份”中恢复为新项目，不覆盖原项目。
   0.7.0 起，备份同时保存 AI 任务的脱敏元数据、版本来源关系、来源事件链和既有来源导出记录；Prompt、密钥与 AI 输出全文仍不写入备份。0.9.0 还保存已归属该项目的移动收集项和动作，并重映射目标场景；未归类项不进入单项目普通备份。1.0.0 保存作者端审阅会话、意见与决定，恢复为只读归档；审阅盐、校验值、项目指纹和恢复短语不进入普通备份。1.1.0 保存冲刺会话、采样、事件、成果和离线小组看板；恢复中的活动冲刺会安全终止，不伪造跨恢复连续计时。1.2.0 保存项目相关的声明式模板包、逐项授权和应用/撤销记录；恢复时节点与应用引用一同重映射，包 ID 碰撞会中止恢复。1.3.0 保存视觉锚点、候选决定、故事板和项目使用的 PNG/JPEG 原始字节；恢复时重新校验内容哈希、真实类型、尺寸、正典版本并重映射实体与场景。图片可能明显增加备份体积。模板包与视觉故事板不含正文或密钥。同步设备身份、恢复短语、密钥盐、验证值、队列和冲突同样排除，防止恢复副本冒充原设备或原审阅会话。

   1.4.0 的研究参与码、同意和任务，以及 1.5.0 的负责人台参与者哈希、声明、提交摘要和删除回执，都是应用级数据，不进入任何单项目 `.bbd-backup`，避免分享项目时夹带研究身份；完整 SQLite 快照仍会保护这些本机记录。退出真实验证或负责人删除只清除当前数据库中的对应记录，已存在的历史数据库快照与产品外原始研究包仍应按保留策略和作者意愿另行处理。
2. 桌面版在启动、正常退出和每 10 分钟创建 SQLite 快照；每个快照都会执行 `PRAGMA integrity_check`。
3. 快照保留最近 20 份，并额外保留最近 7 天每天至少一份。

## 数据库损坏

启动时若主库无法打开或完整性不是 `ok`，应用会停止常规读写并进入“安全救援模式”：

1. 只选择标记为“完整”的快照；
2. 阅读二阶段确认卡中的快照文件名和影响；
3. 确认恢复后，损坏的主库、WAL 和 SHM 会移动到 `recovery` 目录；
4. 恢复副本再次通过完整性检查后才替换主库，随后应用自动回到书架。

若没有有效快照，请保留整个应用数据目录并停止反复启动，不要用空文件覆盖主库。

## 加密接力与丢失设备

1. 在项目“接力”页建立同步身份，并立即把只显示一次的恢复短语保存到密码管理器或离线纸张；不要与 `.bbd-sync` 文件放在同一位置。
2. 输入短语并导出接力包。把文件传到另一台设备后，从书架“接力恢复”创建隔离副本，或在同一项目“接力”页预检并合并。
3. 预检必须显示项目名、发送设备、序号和对象数量；错误短语、缺块、篡改或附件哈希错误都会在落库前阻断。
4. 设备丢失但仍有另一台已解锁设备时，从存续设备导出新接力包，再用恢复短语建立新设备副本。
5. 所有设备和恢复短语同时丢失时，现有接力包无法恢复。0.8.0 没有服务器后门或人工找回。

接力包不是普通备份的替代品：它包含同步状态并用于同一项目跨设备延续；`.bbd-backup` 用于恢复成新的独立项目。0.8.0 仍需手动传文件，真实云端、设备吊销与自动密钥轮换尚未提供。
