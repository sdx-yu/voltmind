# 种子作者波次启动包

本文件供研究负责人执行 R1-C 的首个真实受控波次。笔不怠不保存姓名、邮箱或招募关系；名册、邀请、同意原件和安全交付记录必须位于产品外的受控系统中。

## 启动前硬门

- 负责人已明确且获授权处理名册，只有最少必要人员可访问；
- 目标为 5–10 名真实长篇作者，四类作者分层配额与产品内冻结波次完全一致；
- 每位作者使用自己有权处理的稿件，知悉不会自动上传正文；
- 已演练安装、备份、损坏库救援、支持诊断、退出和外部副本删除；
- 已准备独立的支持渠道与删除联系人，并约定响应时限；
- 波次至少 14 天；四周观察者需要覆盖不少于 22 天和四个有效 UTC 周；
- 任何严重数据丢失、同意争议或越权访问都会暂停招募与证据接收。

任何一项为否，就保持波次草稿，不发送邀请。

## 招募消息模板

> 我们正在进行“笔不怠”本地优先长篇写作工具的小规模受控验证，周期为【起始日】至【结束日】。参与者需要使用自己有权处理的稿件完成实际写作任务，并主动导出不含正文的研究包。工具不要求在应用内填写姓名或邮箱，也不会自动上传稿件。参与完全自愿，可随时退出并要求删除研究负责人持有的外部材料。如愿进一步了解，请通过【受控渠道】联系【负责人角色/编号】；在阅读完整同意说明前不会计入研究。

不要在群发邀请中要求书名、题材细节、正文样本、账号密码或恢复短语。不要承诺收益、出版结果或数据绝对安全。

## 首次交付脚本

1. 单独核对目标作者、独立参与和稿件权利；名册只记录完成核对所需字段。
2. 向作者提供与冻结 Git 提交一致、已通过目标平台门禁的安装包及 SHA-256；不得用聊天软件里的未知转存包替代。
3. 作者首次启动后自行阅读并逐项确认应用内固定同意文本；负责人不得代点。
4. 作者保存参与码到自己控制的位置；负责人不得索要恢复短语、AI Key 或正文。
5. 完成一次测试任务、一次本地备份和一次无正文支持包导出；确认退出/删除路径可找到。
6. 测试材料标记为演练，不计入真实周期；正式任务从冻结窗口内首次真实同意后开始。

## 运行节奏

| 时间 | 作者动作 | 负责人动作 |
|---|---|---|
| D0 | 完成同意、首次备份和真实任务 | 核对分层/波次归属，确认支持可达 |
| D2–D3 | 正常写作并主动导出首个研究包 | 严格预检，只导入人工核对的真实外部样本 |
| D7 | 第二个自然周继续真实任务 | 检查事件链严格扩展、异常与删除请求 |
| D14 | 导出两周末包；决定继续或退出 | 窗口结束后进入复核，不提前关闭 |
| D22–D28 | 四周观察者继续跨周任务 | 核对 4 周、22 天和核心闭环，不催造数据 |

不以每日打卡替代真实任务，不要求作者为了指标重复操作正典闭环。没有新任务时允许没有新包。

## 支持回复模板

> 已收到问题编号【固定异常码】。请先不要卸载、清理应用数据或发送书稿。请导出“无正文支持诊断”，并说明操作系统大版本、问题发生时间和是否仍能打开应用。若涉及疑似数据丢失，请暂停继续写入，按《备份与恢复》只读核对最近快照。不要发送密码、恢复短语、AI Key、正文或完整数据目录。

严重异常必须先在 R1-C 执行台登记固定代码/级别，再按恢复流程处理；解决前不得关闭波次。

## 退出与删除模板

> 已确认你退出本次验证。应用内“退出验证”只删除当前数据库中的参与记录，不影响书稿。研究负责人将于【期限】前删除外部名册关联、原始研究包和支持材料，并提供不可逆删除回执。历史备份/快照和你自己持有的副本需分别处理；如果法律或安全义务要求保留某项，会在删除前说明依据与期限。

执行删除时应同时检查：受控名册、收件位置、工作副本、支持附件、历史导出与备份保留策略。不要仅删除产品内摘要就宣称全部删除。

## 停机规则

立即暂停招募与收包：疑似正文或凭据进入研究材料；真实包与参与者/波次无法核对；事件链分叉；未经同意的访问；两起同类恢复失败；任何未解决严重异常。负责人先隔离材料、记录固定异常、通知受影响者并决定恢复/删除，再考虑重开。

## 最终人工复核

R1-SEED 只有在以下条件同时满足时才可能 PASS：至少 5 名真实作者满足两周规则，至少 3 名满足四周规则，至少 3 名完成跨周核心闭环，数据丢失报告为 0；每份证据来自同一持续事件链并与冻结波次一致；真实身份、独立参与、稿件权利、同意和安全交付由负责人在产品外核对；退出与删除请求已经兑现。

应用聚合数值、自动化、工程夹具、开发者自测、邀请发送量和本文件本身都不算真实作者证据。
