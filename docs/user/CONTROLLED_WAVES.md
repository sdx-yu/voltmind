# 受控波次执行指南

R1-C 是研究负责人的本机波次控制台，不是招募、身份认证或消息系统。从“R1 真实验证”进入“研究负责人工作台”，再打开“R1-C 波次执行台”。顶部和外部执行摘要始终区分工程演练与真实受控波次。

## 先做工程演练

默认类型为“工程演练（不计数）”。设置 14–42 天窗口、1–10 人目标和总和完全相等的四类作者配额，逐项确认协议、产品外名册、删除联系人、支持/恢复路径已经准备，再创建草稿。

按草稿→招募中→执行中推进；执行中可以暂停、进入复核或取消。异常只能选择固定代码和低/中/高/严重级别，不输入作者、书稿或问题自由文本。未解决严重异常会阻止关闭。演练波次和工程夹具无论数量或周期都不会进入真实执行统计。

## 启动真实受控波次

只有研究负责人已经在产品外建立访问受控名册、安全交付渠道、同意记录、退出/删除联系人和支持流程，才选择“真实受控波次”。真实目标为 5–10 人；创建后类型、UTC 窗口、目标、分层配额和协议哈希冻结。

真实研究包必须满足：人工核对的外部证据、同意时间位于冻结窗口、分层仍有配额、波次处于接收状态、参与者没有归属其他波次。同一参与者首次归属后不可换波次。窗口结束前不能进入复核或关闭；任何数值都不会自动把 R1 改为 GO。

## 产品外边界

“导出无名册波次包”只提供冻结窗口、配额、协议哈希、参与者清单和负责人边界，不含名册、参与码或个性化邀请。姓名、联系方式、招募/同意原件、原始 `.bbd-research` 和安全交付记录必须保存在产品外的受控位置，并按同意和保留策略删除。

产品中的工程演练、草稿、波次包、截图和自动化结果只证明执行能力可用。只有归属真实受控波次且由负责人核对的外部研究包，才可能进入真实人数和周期门；仍需人工复核。
