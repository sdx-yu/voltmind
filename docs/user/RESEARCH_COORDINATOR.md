# 受控种子研究台指南

R1-B 是研究负责人本机使用的证据执行台，不是账号、招募或遥测系统。进入“R1 真实作者验证”，再选择“研究负责人工作台”。顶部持续显示 R1 NO-GO。

## 导入

1. 选择作者主动交付的 `.bbd-research`；系统先验证严格 Schema、整包哈希、事件链和任务语义，预检不等于计数。
2. 工程测试、浏览器演练和开发者自测保持“工程夹具（不计数）”。
3. 只有你已经在产品外核对目标作者、独立参与、稿件权利和真实周期，才改成“人工核对的真实外部样本”，逐项确认四项声明。
4. 选择固定作者分层、R1-C 波次（如适用）与 1–365 天保留期限，再确认导入。首次证据类型、分层、波次和同意回执会固定，不能靠后续包静默更换。真实包只能进入真实受控波次，夹具只能进入工程演练，且不能突破冻结分层配额。

同一作者的后续包应来自同一个持续参与码。相同包会幂等忽略；新包必须完整包含旧事件链并继续追加，回退、分叉或同意变化会被拒绝。

## 读门禁

两周资格要求至少两个有成功任务的 UTC 自然周，且同意到最近成功任务跨度不少于 8 天；四周资格要求至少四周且跨度不少于 22 天。跨周核心闭环还要求至少两次成功正典闭环。

试点数值是 5 名两周、3 名四周、3 名核心闭环、0 个数据丢失报告。这比原商业门的 20 人/12 人四周更小，只决定是否值得继续研究。数值达到仍需人工复核，R1 不会自动变为 GO。

## 删除、保留与导出

参与者退出时在摘要表执行二次确认删除；到期记录可批量清除。删除会移除该参与者全部提交摘要，只保留不可逆回执并阻止误重导入。历史 SQLite 快照和你在产品外保存的原始包不会自动删除，须按同意与保留策略另行处理。

“导出聚合报告”生成 `.bbd-cohort`，不含参与码原文、原始研究包、正文、标题、项目/任务 ID、Prompt 或密钥。它只供人工审计，不是身份、研究结论或公开发布证明。
