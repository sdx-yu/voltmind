# ADR-007：用声明式最小能力包实现本地结构模板

状态：已接受（1.2.0）

## 背景

原始调研把插件/模板市场和共享剧情结构列为 V2 方向。当前产品没有发布者账号、签名服务、恶意包扫描、审核下架或供应链响应能力。直接运行第三方 Node/JavaScript 会把本地优先写作工具变成可读取正文、密钥和数据目录的代码执行入口。

## 决策

1. 1.2.0 只实现本地声明式 `bbd-template-v1`，不执行包内代码；
2. 包只描述空白章节/场景和两类固定本地规则，结构资源按 SHA-256 内容寻址；
3. 能力白名单仅为读取当前项目摘要、创建计划节点、运行固定本地规则；安装后仍按项目逐项授权；
4. 正文、网络、密钥、任意文件系统和系统命令没有能力标识，也不能通过配置绕过；
5. 应用前生成绑定当前书稿树的预览哈希；标题冲突要求显式改名；应用单事务完成；
6. 整批撤销使用项目回收站，停用/卸载不影响既有节点和历史；
7. 本地目录明确显示“发布者自述、非认证身份”，不伪造在线市场信号。

## 后果

- 作者可以低风险交换并复用剧情骨架；
- 包即使恶意构造也没有代码执行面，严格 Schema、大小上限、引用检查和哈希在落库前阻断；
- 能力有限，因此暂不支持复杂插件 UI、自定义脚本或第三方网络集成；
- SHA-256 不证明作者身份或许可证真实性；
- 若未来开放代码插件，必须另建隔离运行时、签名/撤销、权限提示、审计和应急响应体系，不能把 v1 静默升级为可执行格式。
