# ADR-003：加密接力包与分层冲突模型

- 日期：2026-08-27
- 状态：接受，V1-S 工程验证

## 背景

笔不怠以本地 SQLite 为主副本。直接引入账号、云数据库和实时协作，会同时放大丢稿、隐私、密钥恢复与业务冲突风险；把全文按“最后写入者胜”覆盖，也不能满足长篇作者对正文、正典和来源记录的不同语义。

## 决定

- 固定 `bbd-sync-v1` 接力协议；0.8.0 以手动 `.bbd-sync` 文件验证协议，不部署云服务；
- 每项目生成 192 bit 随机恢复短语，仅在初始化时显示一次；本机只保存随机盐和 HMAC 验证值；
- 使用 scrypt（N=32768、r=8、p=1）派生 256 bit 密钥，使用 AES-256-GCM 加密完整载荷；信封头作为 AAD，密文按 64 KB 分块并逐块 SHA-256；
- 正文采用 Yjs `Y.Text` 更新合并；版本向量判断先后、重复和并发；
- 正典并发修改、删除/编辑与来源链分叉进入显式冲突，禁止静默覆盖；
- 导入原稿等附件使用 `sha256:<digest>` 内容地址，落库前复核字节数和哈希；
- 普通 `.bbd-backup` 不包含同步设备身份、密钥盐、验证值或更新队列。恢复出的普通备份是新项目；跨设备身份恢复只通过恢复短语和接力包完成。

## 后果与回滚

- 优点：云端或文件中转方看不到项目标题、正文、正典、来源事件和附件明文；重复包幂等；正文可自动收敛，业务冲突保留作者决定权。
- 代价：恢复短语丢失即无法解密；来源链分叉只能保留/知悉，不能伪装成单一连续历史；0.8.0 需要手动传递文件，不具备实时在线体验。
- 回滚：同步表为 migration v8 的附加状态，不改变单机正文与 `.bbd-backup-v2` 路径；关闭“接力”不影响本地写作。

## 外部门

真实云服务、账号生命周期、两台真实设备断网/睡眠/升级矩阵、隐私协议、安全审计和跨地区合规必须单独验收。单机双库模拟不等同于这些门禁通过。
