# ADR-004：移动端双层本地存储与事件并集

- 日期：2026-08-27
- 状态：接受，V1-M 0.9.0

## 背景

移动端必须在桌面服务关闭、网络中断或 PWA 更新期间继续记录，同时不能让离线副本直接覆盖正文、正典或来源链。仅把请求排进内存队列无法承受浏览器关闭；让移动端直接持有完整 SQLite 又会复制桌面复杂度。

## 决策

- 移动 PWA 以 IndexedDB `bibudai-mobile-v1` 保存收集项、动作事件和只读场景缓存；所有用户写入先在本机事务完成，再尝试访问 API。
- 服务端 migration v9 以 `mobile_inbox_items` 保存不可变收集项，以 `mobile_inbox_actions` 保存追加式决定。对象 ID 由来源设备生成；同 ID 同载荷为幂等重复，同 ID 异载荷拒绝为冲突。
- 当前状态不是可覆盖字段，而是按 `created_at,id` 对动作事件确定性折叠的投影。乱序和重复导入不改变结果。
- `bbd-sync-v1` 载荷新增可选 `mobileInbox`。可选字段保持 0.8.0 接力包可读；项目收集项和未归类项通过既有 AES-256-GCM 接力包做并集。
- 移动端只能创建灵感、场景想法和私有审阅笔记，读取缓存正文并做显式处理决定；它不能直接修改正文、正典或来源事件。
- Service Worker 在安装阶段原子缓存入口、哈希资源、清单和图标；新 worker 只有收到用户确认消息才激活。激活后保留当前 shell 与一个上一版本 shell。

## 后果

- 优点：断服和断网时可写，浏览器重开不丢；同步重放天然幂等；移动端能力边界可审计。
- 代价：离线设备的项目/场景目录可能陈旧；未归类项在 V1-M 的单作者模型中随首个项目接力包并入，未来多项目并行中继需增加独立收集箱流。
- 恢复：缓存异常可由用户显式重建；重建会清除尚未回流的本机记录，因此 UI 必须先告警。低于约 2 MiB 可用配额时只提示释放空间，不声称新记录已保存。
- 外部门：手机访问所需的 HTTPS/LAN 或云中继、真实 iOS/Android 安装矩阵、设备吊销与账号恢复均不属于 0.9.0。
