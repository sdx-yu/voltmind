# ADR-005：用双向离线包实现角色化审阅接力

状态：已接受（V2-R 1.0.0）。

## 背景

原始调研把 Editor、Beta Reader、Co-Writer 和段落级批注列为 V2 的第一项。当前产品没有账号、成员目录、云端中继与在线鉴权；直接做“邀请”和“权限”界面会制造并不存在的安全边界。

## 决策

采用 `bbd-review-v1` 双向加密包。作者创建有明确角色与场景白名单的 assignment；审阅者导入为 `projectId=null` 的隔离快照，只能产生角色允许的反馈；作者导入 response 后逐条决定。所有外部意见默认只读，接受局部建议才写入新版本和来源事件。

锚点采用段落哈希、引用、上下文和偏移的组合，并公开 exact/candidate/lost 三态。系统宁可要求人工定位，也不在正文变化后猜测。

## 后果

优点：在没有服务端身份系统的前提下形成可测试的最小授权和作者最终决定闭环；包可通过任意用户选择的渠道传递；普通备份保留审阅历史但不保存密钥材料。

代价：离线副本发出后不可撤回；审阅者身份是作者填写的标签，不是经过认证的账号；无法实时看到新正文或多人光标；恢复短语丢失后不能重开原包。

## 拒绝的方案

- 伪造本地“成员账号/邀请”：没有远端认证与撤销能力，安全语义不成立；
- 直接复用 `bbd-sync-v1`：同步协议复制完整项目，授权面过大，也没有作者逐条决定语义；
- 直接应用文本补丁：正文漂移时可能误改，且绕过作者确认与来源记录。
